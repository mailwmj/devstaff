# 网站独立检查

## 协作契约

交接或恢复会话时读 [上下文契约](../site-brief/references/context-contract.md)，按统一回执 schema 返回，不另建上下文副本。

| 字段 | 本 Skill 的接口 |
| --- | --- |
| `reads` | 冻结源码、brief、页面设计合同、实施计划、`state.py show` 与验证规则；第三方无状态项目不初始化 |
| `writes` | 仅 `.site/checks/` 内自己的凭据；不写源码、状态或恢复快照 |
| `schema` | 回执为 `passed / failed / incomplete / blocked`；矩阵含 profile、原因、browser、逐项 axis/status/blocking/evidence |
| `handoff` | 矩阵与发现交回 `site-builder`；失败供 `reopen --check`，通过仅供交付判断；直接验收到报告为止 |
| `evidence` | 命令/检查 `check_id`、产物哈希、操作记录与页面/状态/视口；声明与单张截图不替代运行证据 |

检查实际成果，不根据代码意图、文件存在或构建成功推断用户任务可用。此 Skill 始终只读；修复由 `site-builder` 完成后再次调用本 Skill。

## 执行

1. **确定对象和范围。** 定位用户指定项目，读取源码、原生说明、`.site/brief.md`、`.site/design/surface-brief.md`、`.site/implementation-plan.md` 和状态。页面设计合同是方向、页面、区块、状态、响应式、文案、素材和视觉验收的共同接口；没有 `.site` 的第三方项目仍可从请求与工程检查，不初始化、迁移或补写。
2. **建立检查矩阵。** 读 [验证规则](references/verification.md)，先建立本轮适用来源清单，核对每条首版承诺、原型补齐事项与正式实现位置，再选择 `smoke`、`targeted` 或 `full` 档位并写明 `profile_reason`；来源清单逐条映射到矩阵项。声明 `browser.available`：可用时记录真实 provider，不可用时记录具体限制，不为验收临时要求用户安装浏览器。按现有材料选用真实浏览器、当前版本截图、静态检查与项目原生测试；截图只能辅助核对可见结果，不能证明点击、动态状态、持久化或再次打开。把每项能力写成“前提 → 操作 → 可观察结果”，标明 `axis` 与是否阻断交付。新建、整体改版、主流程或信息结构变化还须把页面设计合同中适用的 `IC-* / PG-* / SC-* / RP-* / CP-* / TX-* / AS-* / VA-*` 映射到矩阵；合同缺少适用内容属于交接失败，不能由 Checker 猜测补齐。小范围文案、颜色和间距调整通常使用 `smoke`；单个交互、计算或局部 Bug 使用 `targeted`；新建、重大结构变化、持久化、权限、隐私、导入导出或共享数据使用 `full`。`full` 始终列出 `static_build / core_task / visual_desktop / visual_mobile / reopen` 五个轴；浏览器可用时五轴均阻断，不可用时视觉和再次打开轴以非阻断 `not_run` 如实保留。`static_build` 与受影响的 `core_task` 始终阻断；如果核心任务只能在浏览器中证明，缺少浏览器仍会阻断交付。
3. **静态与构建。** 沿用项目原生命令；静态网页可用本 Skill 的检查脚本。该脚本会对 UI 容器和常见 UI 文本注入点机械拦截 Emoji 图标（`emoji-in-ui` / `emoji-in-ui-sink`）；用户正文中的 Emoji 不在扫描范围内。命令成功只证明该命令，不能替代业务和视觉轴。
4. **核心业务。** 优先使用宿主已有的真实浏览器；没有时使用项目原生测试、命令或可归档结果完成仍可证明的核心任务和高价值反例。可见控件必须兑现承诺，不能用静态阅读替代必须点击或渲染才能证明的行为；持久化、导入导出或复杂交互若没有等价运行证据就标为阻断 `not_run`。未经授权不提交外站表单或修改真实数据。
5. **视觉审查。** 有真实浏览器时调用 `site-design` 的只读审查分支，传入页面设计合同、代表页面、关键状态和目标视口，逐条核对 `VA-*` 并覆盖合同里的响应式与组件状态。结构已确认但风格待选时，不得按已确认视觉做方向匹配判定。Checker 不直接查询内置设计库，也不重新选择风格；合同缺少来源或可观察标准时按交接缺失处理。该分支不得调用 `site-brief`；没有真实渲染时将桌面和手机视觉轴作为非阻断 `not_run`，不得根据 HTML/CSS 推定通过。
6. **再次打开。** 有真实浏览器时从交付入口重新启动或打开，核对运行说明、入口、关键数据和限制。没有浏览器时保留非阻断 `not_run`；若再次打开承载持久化等首版核心承诺，则同时把对应 `core_task` 标为阻断 `not_run`。开发服务器当次可用不等于可再次使用。
7. **报告。** 每项记录前提、操作、预期、观察、状态、`axis`、是否阻断、证据与限制；回执说明本轮档位及选择原因，并按影响排序 failed 项。每项证据写清它来自哪个真实产物（截图、结果 JSON、日志）或哪次 `check.py static/run` 的 `check_id`，再交给 `check.py matrix --profile <smoke|targeted|full>` 生成内容寻址矩阵凭据；阻断项可用 `artifact`、`command` 或 `check` 证据，写不出证据的项标成 `not_run`。验证较久时在开始新检查轴、发现阻断项、进入修复复验时报告一次阶段变化，不把命令流水逐条转给用户。回执带上 `check_id`。摘要校验只用于发现误改，不把它称为签名或恶意 Agent 防护；证据是否真正支持语义结论仍由本 Skill 判断。重要检查未执行或核心任务失败时不能称全面通过，也不写任何协作状态；本 Skill 唯一的写入位置是 `.site/checks/` 下自己的检查凭据。

## 协作回执

返回：`passed | failed | incomplete | blocked`、检查矩阵与 `check_id`、阻断项、非阻断建议、实际入口、未执行项及恢复条件。被 `site-builder` 调用时只返回发现；用户直接验收时到报告为止。宿主支持独立 Agent 时优先隔离检查上下文，不支持时说明独立性限制。

按验证规则先建立本轮适用来源集合，再逐条映射到实际矩阵项，随契约的 `coverage` 返回；保留原型模拟/缺失项的正式去向，不只检查原型已有控件。差异及上游修复问题按 `findings` 返回预期、实际、位置与本轮冻结版本的复验结果。非阻断失败只按规则明确保留并披露，`not_run` 与无发现均不改写为通过。

截图不是操作证据，代码推断不是视觉检查。真实浏览器是条件能力：可用就完成视觉、交互与再次打开实测；不可用就完成仍能可靠证明的部分，并把浏览器轴作为非阻断 `not_run`。缺浏览器不能豁免受影响核心任务，无法以等价证据证明的核心承诺仍是阻断 `not_run`。连续两次复验没有新证据时返回 `blocked`，不盲目重试。
