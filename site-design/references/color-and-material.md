# 色彩推导与素材

两件让页面"看起来像真东西"的事：颜色有来源，素材是真的。两件都做不到时，页面还能勉强成立；只有一件做不到，它就开始像模板。

使用时机：[视觉方向](visual-direction.md) 第四步。局部色值调整不做完整推导。

## 一、色彩

### 1. 三步法：采样 → 收敛 → 论证

**采样。** 从真实来源取色，不凭空发明。可用来源按证据强度排：

| 来源 | 说明 |
| --- | --- |
| 项目已有的品牌色板、VI、设计系统 token | 最高优先。已有系统时只做语义映射，不引入第二套全局变量 |
| 现有产品页面或截图里可直接读到的颜色 | 只能对可见色值声称精确 |
| 用户提供的真实素材（实拍、印刷品、产品照片） | 从像素采样，记录取自哪张图 |
| 业务对象的材料属性 | 器物、纸张、植物、场所的实际颜色，属于 `derived` |
| 调色板类的实现校准目录（`tokens.json`） | 只做校准起点，不构成方向 |

**收敛。** 把采样色整理成**语义角色**，而不是一组并列的颜色。角色和它们之间的关系比具体色值重要：

- 表面层：canvas（页面底）→ surface（内容面）→ surface-raised（抬起的面）。三层之间靠明度或色温拉开，不靠阴影堆叠；
- 文字层：text（主要）与 text-muted（次要）。两者都必须对每一个表面层达标；
- 强调层：accent（品牌或主操作）、on-accent（压在强调色上的文字）、accent-hover、selection / on-selection；
- 边界层：border（非关键分隔）与 border-control（需要被辨识的控件边界）职责不同，不能互相替代；
- 焦点层：focus，必须与前后景都可辨识；
- 状态层：success / error / warning 及各自的 surface。**状态色不参与品牌表达**，也不得用品牌色顶替全部状态。

明度关系要成体系：canvas 与 surface 的差距足够看出层次但不能刺眼；text 与 canvas 的对比最大；text-muted 明显弱于 text 但仍达标；border 弱到不抢注意力，border-control 强到能被看见。

**论证。** 每个颜色都要能说出它从哪来。说不出来就是凭空发明——凭空发明的颜色会让项目识别度下降，也是"同一个模板换个产品名"的主要来源。

### 2. 数量与分布

- **一个强调色贯穿全页。** 第二个强调色需要有明确的功能理由（例如区分两个对立的业务状态），不是为了丰富；
- 内容页控制强调色的面积。强调色的作用是引导，不是装饰；
- 状态色只在状态出现的位置使用，不做背景装饰；
- 颜色数量失控（十几种互不相关的色）通常意味着颜色不是从同一个来源收敛出来的。

### 3. 必须实际检查的

配色不能只在 token 表里检查。**必须检查渲染后的实际相邻色对**：文字与它真正落在的背景、按钮文字与按钮背景（含悬停态）、链接与正文、边框与它相邻的表面、焦点环与前后景。

- 正文与实际背景对比度按可访问性下限要求，这是硬下限；
- 控件边界与焦点需要可辨识；
- 深色主题**不是亮色的反色**。反色会得到刺眼或发灰的结果，必须重新调整彩度、对比与强调色；
- 半透明叠层、图片上的文字、动态状态、色觉辨识不在自动检查范围内，必须人工看；
- 自动色对检查通过**不代表**整页无障碍合规，也不代表设计通过。

### 4. 强度分级

- **硬下限**：实际相邻文字与其背景的可读性、状态不只用颜色表达（必须附文字或图标）、深色主题的独立校验；
- **条件性风险**：品牌色与可访问性冲突时的取舍（需说明并让用户知情）、第三方库色值格式与主题 API 的适配；
- **可覆盖启发式**：具体的采样来源、明度与彩度关系、配色数量。项目已有设计系统或品牌规范时以它们为准。

## 二、素材

内容型页面（课程、展览、器物、人物、地点）的视觉质量很大程度由素材决定。素材缺失时，构图和配色再对也撑不起来。

### 1. 获取顺序

按优先级取，不要跳过前面的层级：

1. **用户已有素材**。先问。用户手里的实拍和真实材料永远优于任何外部来源；
2. **一手来源**。产品官网、官方图片库、机构或场馆公开的图片与资料；
3. **公共领域与免版权素材库**。使用前确认许可范围，并记录许可本身；
4. **生成素材**。仅在用户确认可用该能力时使用，且必须以真实参考为依据；
5. **诚实缺图状态**。前面都拿不到时使用。

**未经授权不提交表单、不创建账号、不抓取需要登录或明确限制的内容。** 需要联网获取时按宿主实际能力进行，不擅自扩大权限；拿不到就退到下一级，不要绕。

### 2. 必须记录

每个进入稿件的素材都要能回答：

```text
来源：URL 或用户提供的文件名
性质：实拍 / 官方素材 / 公共领域 / 免版权 / 生成 / 示例
许可：许可名称或"用户授权"，以及获取日期
作者或权利方：
用途与裁剪：用在哪一页、怎么裁的、改了什么
```

许可不清或来源不明的素材不进稿件。用不了的素材如实说明缺口，不拿来源可疑的图凑。

### 3. 真图诚实性测试

在决定用一张图之前问：**去掉这张图，信息是否有损？**

- 有损 → 它是内容素材，用它；
- 无损 → 它只是氛围或装饰，通常不该加。用来"填空"的图会削弱而不是提升页面；
- 尤其警惕把通用素材图当作内容证据：它不证明场地、师资、产品能力或客户评价存在。

### 4. 裁剪与呈现

- 按**用途**裁，不按原始比例硬塞。同一张素材在不同位置可能需要不同裁切，焦点要保住；
- 比例、清晰度和裁切必须成套：列表缩略图、首屏主图、详情大图各自定规格，不要一张图缩放三处；
- 为窄屏准备局部或替代裁切，不要靠 `object-fit` 把主体切成一半；
- 图片必须有替代文本；纯装饰图用空 `alt`；
- 缺图时设计**有尊严的缺失状态**（说明缺什么、何时补），不要用灰色色块冒充真实图片，也不要把色块标注成素材。

### 5. 禁止

- 编造用户履历、客户评价、成交数字、报道与认证；
- 用生成或示意素材冒充真实人物、真实场景、真实产品能力或证明材料；
- 把参考站的内容直接搬进交付物；
- 发布时把不应公开的参考材料一并带出。

### 6. 强度分级

- **硬下限**：来源与许可可追溯、不伪造证明材料、不冒充真实素材、替代文本；
- **条件性风险**：生成素材的使用（需用户确认能力）、外部素材的公开使用；
- **可覆盖启发式**：具体渠道选择、裁切比例、同一素材的复用次数。

## 三、交接

把色彩来源与语义角色、素材清单与许可状态写进 [页面方向合同](surface-brief.md)，并随稿件说明**哪些素材是示例、哪些缺口未补**。用户确认的是他看到的实际页面，不是色板或素材清单。
