# 排版：中文优先的字面工艺

排版是视觉质量里最容易被跳过、也最容易露怯的一层。一个页面的构图和配色可以靠直觉蒙对，字面不行——它由一串具体决定组成，每个决定都能被看出来。

本包不随附字体二进制；实际项目可以沿用已有字体、打包字体、CDN 字体或系统字栈。先做**角色分配**，再按真实分发条件选择具体字族，并为加载失败准备回退。

使用时机：方向合同确定之后、正式实现之前。局部文案改动不需要重做。

## 1. 角色表

先定角色，再挑字族。一个页面通常不需要超过三个字族。

| 角色 | 承担什么 | 要求 |
| --- | --- | --- |
| display | 一页最多一处的最大字 | 尺度足以承担构图；不用于需要逐字阅读的长句 |
| 标题 | 层级入口 | 与正文有可辨的字号、字重、颜色差异 |
| 正文 | 连续阅读 | 中文行高与行长按本文件中段规定 |
| UI | 控件、导航、表格、表单 | 与正文可以同族，但字重与字号自成体系 |
| 数据 | 数字、金额、时间、编号 | 等宽或表格数字（`font-variant-numeric: tabular-nums`），保证纵向对齐 |
| 代码 / 标识 | 代码、ID、版本号 | 等宽 |

中文可用的本机字族（含回退，按平台顺序写）：

| 类别 | 字栈 | 常见于 |
| --- | --- | --- |
| 黑体 | `system-ui, -apple-system, "PingFang SC", "Microsoft YaHei", sans-serif` | 界面、正文、标题 |
| 宋体 | `"Songti SC", "SimSun", "Noto Serif CJK SC", "Source Han Serif SC", serif` | 标题、长阅读正文 |
| 楷体 | `"Kaiti SC", "KaiTi", "STKaiti", serif` | 手记、文化、教育语境的标题或引文 |
| 等宽 | `ui-monospace, SFMono-Regular, Consolas, monospace` | 代码、编号、数据 |

**必须实际查看回退效果**：同一段文字在 mac 与 Windows 上会落到不同字族，字重和字宽都不同。只声明字栈不算验证过。

## 2. 字阶

字阶是**比例**，不是一组固定像素。为项目定一条比例（常用 1.2 / 1.25 / 1.333），从正文出发向两边推。

- 正文是基准。中文正文 **16px 起**；界面内辅助文字 14px；注释与标签 12px，且**不承担主要阅读**；
- 移动端正文 16px 起，低于 16px 会触发部分浏览器的自动放大，也会让中文笔画发糊；
- display 与正文之间**至少 2 倍**差距才有构图作用。相差 1.3 倍的"大标题"只是更大的标题；
- 层级数量控制在三到四层。层数越多，每层的差异越弱，最后等于没有层级；
- 字号只承担尺度，不承担全部层级。**至少两项差异同时作用**（字号 + 字重、字号 + 颜色、字重 + 间距）才算清楚的一层。

`tokens.json` 的 typography profile 提供角色分配的起点和一套字阶，不是必须照抄的数值；项目已有设计系统时以项目为准。

## 3. 行高与行长

| 文字类型 | 行高 | 说明 |
| --- | --- | --- |
| 中文正文（连续阅读） | 1.7 – 1.9 | 汉字是满格方块，行高低于 1.6 会挤 |
| 界面正文（短句、列表） | 1.5 – 1.6 | |
| 标题 | 1.2 – 1.35 | 多行标题取上限，单行可取更紧 |
| 表格与数据行 | 1.4 – 1.5 | 配合行高 token 与 `tabular-nums` |
| 西文连续阅读 | 1.5 – 1.7 | 与中文同页时取两者中更宽松的 |

行长（度量）：中文连续正文 **每行约 30 – 40 字**。用 `em` / `ic` 表达上限（如 `36ic`），不要用固定 px，否则窄屏和放大字号时失效。行长过长的正文是最常见的可读性问题：内容页面在宽屏下必须限宽，不能铺满。

## 4. 字距

- **中文标题字距默认 0。** 汉字是等宽方块，负字距会让笔画相撞，直接照搬英文大标题的 `-0.04em` 是典型错误；
- 西文为主的 display 可以轻微收紧（约 `-0.01em` 到 `-0.02em`），且必须实际查看，不凭规则数字；
- 中文**加**字距只用于极短的装饰性拉丁标签；用于中文正文会破坏阅读节奏；
- 全角标点与半角字符混排时不要用 `letter-spacing` 补救，见下一节。

## 5. 中文排印细节

这些是最能区分"有审校"和"随手生成"的地方：

- **引号**：正文用「」和『』，不用英文直引号；代码与英文文本内保留英文引号；
- **标点**：中文语境用全角标点。不要在中文句子里混入半角逗号、问号、括号；
- **避头尾**：行首不出现 `。，、；：？！）》」` 等收尾标点，行尾不出现 `（《「` 等起始标点。CSS 的 `line-break: strict` 与 `word-break` 能覆盖一部分，其余靠文案和容器宽度调整；
- **中西文之间**：中文与拉丁字母、数字之间留出视觉间隙。浏览器的 `text-autospace` / `text-spacing-trim` 支持有限且不一致，**不要承诺自动生效**；可靠做法是在文案里加半角空格，或对必要处用带样式的 `<span>`；
- **数字与单位**：数值与单位之间留细空隙（如 `12 人`、`399 元`），表格列用 `tabular-nums` 对齐；
- **省略号与破折号**：用 `……`（六点，两个全角）和 `——`（两个全角），不要用 `...` 和 `--` 顶替；
- **中英混排的字重**：同一个字重值在中文黑体和西文无衬线里视觉重量不同，混排标题需要实际对比后再定，不能只写一个数字。

## 6. 层级与细节

- 标题的换行由内容决定：短标题避免孤字成行，可用 `text-wrap: balance`；正文用 `text-wrap: pretty` 减少孤行。这两个声明不改变布局，属于低风险的排版改善；
- 长英文串、URL、ID 必须能断行，否则会把容器撑破（`overflow-wrap: anywhere`）；
- 数字、金额、日期在列表和表格里必须纵向对齐，这是"像真实产品"最直接的信号之一；
- 标题与它所属内容之间的间距**必须小于**它与上一块内容的间距。间距关系错了，层级再清楚也会被读错。

## 7. 强度分级

按 [设计质量](design-quality.md) 的三档理解本文规则：

- **硬下限**：中文正文字号下限、行高下限、实际相邻色对的可读性、数字对齐、标点与引号规范、`overflow-wrap`。这些在任何风格下都必须满足；
- **条件性风险**：字体加载方式与分发条件、字体缺失时的回退表现；
- **可覆盖启发式**：具体字阶比例、字族配对、行长数值、字距微调。项目已有设计系统、明确参考或有依据的品牌规范时，以它们为准，但必须能说明依据。

## 8. 常见错误

| 表现 | 为什么是问题 | 改法 |
| --- | --- | --- |
| 四套排版方案只是同一组系统字体的不同字号 | 没有角色分配，等于没有排版决定 | 按第 1 节重新分配角色，制造一个真实差异 |
| display 用系统默认黑体并配 1.3 倍字号 | 没有构图作用，页面看起来像 demo | 拉到 2 倍以上，或换角色承担 |
| 中文标题写负字距 | 笔画相撞，是照搬英文的痕迹 | 归零，改为用字号和字重制造对比 |
| 正文行宽铺满宽屏 | 超过 40 字后回扫困难 | 限宽，用 `em` / `ic` |
| 12px 的中文承担主要阅读 | 笔画糊，可读性不足 | 提到 16px，或缩短文案改为标签 |
| 每个层级只差一点字号 | 层级读不出来 | 减少层数，让每层差异可辨，并叠加字重或颜色 |

排版做对不等于页面好看，但排版做错一定不好看——它是后面所有判断的前提。
