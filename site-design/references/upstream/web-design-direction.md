# 完整网页设计交付

本文件由项目内提供的 `web-design-direction` 直接本地化而来。它定义 `site-design` 在新建网站、整体改版或缺少成熟设计系统时必须交出的设计内容；四个 `site-*` Skill 的门禁、状态文件和职责分工始终优先。

## 内置设计栈

- [Impeccable 工艺下限](impeccable-craft-floor.md)：完成度、排版层级、状态、响应式和收尾质量。
- [UI/UX Pro Max](ui-ux-pro-max.md)：通过本地检索库扩大风格、色彩、字体、交互和技术栈候选。
- [ClawHive 设计原则](clawhive-frontend-design.md)：视觉命题、一个记忆点、构图优先和反模板检查。

三者组合使用，不把任何一套预设直接当作项目答案。实际加载和查询结果必须写入页面设计合同的“设计方法来源”。

## 使用流程

1. **先收集背景。** 理解网站目的、目标用户、使用情境、行业约束和已有品牌资产。存在 Logo、颜色、字体、素材、旧站或真实内容时先提取并尊重；缺少会改变首版范围或高风险边界的信息时交给 `site-brief`。
2. **先形成项目方向。** 用内容事实、视觉世界、母题、构图命题和一个记忆点描述为何这个页面属于当前项目。写不出项目特异性时继续补事实，不用“现代、简洁、高级”或随机预设填空。
3. **默认给一个推荐结构。** 只有结构差异会改变主任务或重要取舍时才增加候选。结构确认后，在同一结构、内容和状态上默认给两个母题层真正不同的视觉方向；第三个只在能回答新问题时出现。
4. **把候选做成可点击 HTML 体验稿。** 文件自包含或使用项目内可追溯资源，展示真实视觉质感、代表内容、主要交互状态及目标宽窄视口。它是设计评审稿，不是正式源码。
5. **视觉确认后补全同一份页面设计合同。** 不另建平行规格，也不增加新的用户确认。

## 完整交付内容

以下内容全部写入 `.site/design/surface-brief.md`；体验稿作为合同引用的独立成果保存。

### 1. 方向摘要

- 选定方向名称和一句普通用户能理解的气质描述；
- 它为何适合当前使用者、主任务和内容；
- 3～5 个参考特征，以及它刻意弱化或牺牲的内容。

### 2. 可点击体验稿

- 接近成品的自包含 HTML；
- 展示标题与正文排版、主要色彩、间距节奏和至少一个真实交互状态；
- 固定代表内容与业务状态，使候选可以公平比较。

### 3. 页面地图 `PG-*`

按顺序列出首版页面。每页记录用途、主任务或转化、`primary | secondary | utility` 优先级，以及动态数据或 CMS 需求。

### 4. 区块清单 `SC-*`

按页面顺序列出区块职责、内容类型和来源、布局模式、状态与动态数据。每个区块只有一个主要职责和一个主要行动或结论。

### 5. Design Token

- 颜色：画布、表面、正文、次要文字、强调、边界、焦点和意图状态；
- 排版：标题、正文、界面、数据或代码角色的字族、字号、行高、字重及中文回退；
- 空间：基础单位、间距档、容器、栅格、gutter 和阅读行长；
- 形状与层次：控件、卡片、弹层的圆角、边框、阴影和层级；
- 动效：共享节奏、用途和减少动态效果后的结果。

### 6. 响应式合同 `RP-*`

断点从内容开始失效的位置得出，至少覆盖 375px、768px 和 1440px。记录栅格、导航、内容重组、主行动与素材裁剪；移动端不得靠隐藏核心信息假装适配完成。

### 7. 组件状态 `CP-*`

只列实际出现的交互类型。按适用性覆盖默认、悬停、按下、焦点、禁用、加载、成功、错误、空和极端内容，并记录键盘、触控和可访问名称。

### 8. 文案台账 `TX-*`

每个文案槽位标注 `user | existing | reference | ai-draft | placeholder`、长度目标及审核缺口。没有来源的价格、履历、评价、数字和承诺不得写成正式事实。

### 9. 素材地图 `AS-*`

映射每个图像或媒体槽位的页面、区块、比例、来源、许可、裁剪和 alt。缺少真实素材时使用与构图一致、有明确来源的代表素材或诚实缺失状态，不用灰框、Emoji 或无来源图片冒充完成。

### 10. 视觉验收标准 `VA-*`

把方向写成可观察断言，绑定页面、状态和视口。最低覆盖选定方向与首屏重心、色值及实际相邻色对、排版角色、空间与栅格、主任务、组件状态、窄屏信息保真、素材清晰度与许可、键盘焦点、触控尺寸和减少动态效果。

## 反模板交接检查

- 页面结构来自当前任务，不是默认的“渐变 Hero + 三张功能卡 + 评价 + CTA”；
- 字体和强调色来自品牌、内容或使用情境，不是无依据的 Inter、白底和通用紫色；
- 方向有具体名字、母题、构图命题和一个服务内容的记忆点；
- 换成另一家产品的名字或 Logo 后不应仍然同样成立；
- 常规 UI 不使用 Emoji 充当图标或装饰；
- 视觉叙事需要图片时使用真实、可追溯、适合实际槽位的素材；
- 体验稿必须在目标桌面和移动视口实际查看，不能用文件存在代替视觉结论。

任何一项不成立，先修正方向或体验稿，再交给用户比较。

## 边界

- `site-design` 只制作体验稿、页面设计合同和只读设计审查；正式工程由 `site-builder` 修改。
- 最终结构和视觉决定属于用户；Agent 可以给有依据的推荐，不能替用户确认。
- 缺失品牌资产或内容时使用清楚标注的原则性占位，不发明品牌事实。
- `site-check` 按同一份合同中的 `VA-*` 验收，不补写设计规格。
