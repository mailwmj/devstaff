# ClawHive 前端设计原则

本文件把用户提供的前端设计方法改写为当前项目的内部设计层。它负责让页面具有明确方向、内容重心和完成度；产品范围、用户确认和正式源码权限仍由四个 `site-*` Skill 管理。

## 分层标准

高质量不是一次“做得现代”提示，而是三层共同作用：

1. **Web 基础系统：** 上下文优先、响应式栅格、4/8px 间距、Semantic Token、WCAG 2.1 AA、桌面与移动行为。
2. **审美提升：** 有依据的色彩、动态张力、排版反差、留白、材质、图像与动效方向。
3. **反模板门禁：** 在交接前检查结构、字体、颜色、素材和组件是否退回类别惯例。

## Direction First

写代码前先确定：

- 用户目标、受众和主要任务；
- 关键内容类型与成功标准；
- 希望产生的情绪；
- 一句 visual thesis：气质、材料和能量；
- 一个用户能记住、且服务内容的视觉动作；
- 页面最短使用路径；
- 2～3 个真正解释状态或强化氛围的 motion idea，静态更合适时明确不加。

每个区块只有一个职责、一个主视觉结论和一个主要行动或信息。方向应具体，如 editorial、industrial、playful、organic、brutalist、retro-futuristic 或 restrained；“clean modern”不是方向。

## 改版诊断

改版前查看真实页面并回答：

1. 当前品牌和用户为何使用它；
2. 颜色是否疲劳、廉价或过饱和；
3. 构图是否过度对称、单调或被组件模板主导；
4. 层级、素材、排版或反馈缺了什么；
5. 页面是否静态到失去反馈，还是动效会妨碍任务；
6. 哪些产品行为、内容和品牌资产必须保留。

## Layout And Spacing

- 从构图开始，不从卡片开始。
- 优先使用区块、列、分隔线、列表和媒体；只有内容具有独立操作、选择或状态时才使用卡片。
- 使用响应式栅格和语义化容器、列、gutter、margin token。
- 外边距保持稳定，内部构图可在有依据时非对称、错位或突破栅格。
- 留白体现关系：相关内容更紧，不同层级更松；高密度界面也必须是受控密度。
- 不在卡片内再套卡片，不把页面区块装成漂浮面板。

## Typography

- Typography 承担主要视觉层级；字族选择来自品牌、内容语言和使用情境。
- 除非项目确有需要，最多使用两个字族；任务型界面通常一个调校良好的字族更稳定。
- 建立 display、heading、subtitle、body、label、data 等语义角色。
- 中文标题默认 `letter-spacing: 0`，不机械照搬英文紧缩字距；连续正文控制可读行长。
- 标题只表达一个意思，支持文案通常保持一句；导航和 CTA 用短、平行、动作明确的词。
- 删除 UI 中的设计说明、提示词和重复营销套话。

## Color

- 从 `canvas / surface / text / accent / state` 等语义角色建立颜色，不在组件里散落色值。
- 颜色来自品牌、真实素材或业务材料；没有来源时从中性基础开始，并标记为推导。
- 默认一个强调色；多色系统必须有内容或品牌依据。
- 紫色渐变、Neon、高饱和多色或类别默认深色都不是起点。
- 在实际相邻背景上检查正文、次要文字、控件边界、Focus 和状态色。

## Visual Treatments

先用留白、对齐、尺度、裁剪和对比建立层级，再考虑 shadow、blur、gradient、grain、pattern 或 texture。效果必须来自当前视觉世界并保持一致、可读、可运行；装饰不能遮住文字或主要操作。

## Motion And Interaction

- 动效解释进入、层级、状态变化或反馈，不为“显得高级”而存在。
- 默认使用 CSS；复杂 React 叙事可使用项目已有的 Motion / Framer Motion。
- Scroll entry 用 Intersection Observer，不用零散 scroll listener。
- 共享 duration 和 easing token；快速连续操作可以取消并落在正确最终状态。
- `prefers-reduced-motion` 下保持全部内容、状态和操作可达。
- 工具型页面不播放阻碍操作的整页入场编排。

## Persuade 页面

- 首屏让用户立即知道产品或服务是什么、为何可信、下一步做什么。
- 品牌、产品、场所、人物或核心对象必须在第一视口成为明确信号。
- 图像主导时优先全幅真实媒体或一个完整视觉平面，文字放在稳定可读区域；不把 Hero 放进卡片。
- Sticky Header 占用首屏预算；桌面和移动端都应露出下一段内容的线索。
- 默认避免 Hero 卡片、统计条、Logo cloud、过量 Pill、浮动 Dashboard 和没有证据的社会证明。

## Operate 页面

- 第一屏直接进入工作区，而不是营销 Hero。
- 围绕主工作区、导航、次级上下文和一个行动/状态强调色组织。
- 信息可密集，但扫描、比较和重复操作必须稳定。
- 使用功能性标题、状态与行动文案，不写可替换到广告上的口号。
- 默认避免 Dashboard 卡片马赛克、每个区域粗边框、例行界面装饰渐变和多个竞争强调色。

## Read 与 Experience 页面

- `Read` 先保障理解、目录、阅读行长、章节关系和再次定位。
- `Experience` 让作品、场所、产品或媒体从第一视口主导，界面退居辅助。
- 任何沉浸效果都不能破坏导航、回退、性能和移动端阅读。

## Content Authenticity

- 使用真实内容、可信示例和与场景匹配的文案。
- 视觉叙事需要图片时，按区块职责主动寻找真实、授权明确、分辨率足够的素材。
- 检查人物与文化语境、裁剪、文字安放区域、内嵌 Logo/标牌及不同图片之间的一致性。
- 缺素材会改变方向时标记阻断；不阻断时设计诚实缺失状态。
- 不用 Lorem ipsum、灰框、抽象渐变、假 3D 或无来源图片承担核心叙事。

## Responsive And Accessibility

- 同时设计桌面、移动和内容开始失效的中间宽度。
- 文本与状态满足 WCAG 2.1 AA；Focus、Hover、Pressed、Disabled 在相应输入方式下可见。
- 主要操作不依赖 Hover；触控目标至少 44×44px。
- 窄屏重新组织内容，不隐藏价格、时间、状态、风险或完成任务所需信息。
- 装饰效果不能降低可读性，图标按钮有可访问名称。

## Optimization Order

1. 修复被阻断的任务、误导状态和不可访问路径；
2. 重建疲劳、通用或廉价的颜色关系；
3. 用层级、构图与间距解决页面结构；
4. 补齐真实素材、排版角色和组件状态；
5. 只在需要时增加动效、材质、阴影与细节。

## Anti-Patterns

没有项目依据时，不交付：

- 白底紫色渐变、Neon 或均匀 Rainbow palette；
- 安全而重复的对称区块、通用三卡网格或卡片堆叠工作台；
- 默认字体栈承担品牌表达；
- 素材缺失却以 Placeholder-heavy 页面冒充成品；
- 漂亮图片但品牌和产品不清楚；
- 有强标题却没有明确行动；
- 忙乱图片承载正文；
- 无叙事目的的 Carousel、动效和装饰图标；
- 用大量微型 Badge、Pill、图标和说明才能解释的区块。

## Litmus Checks

- 第一屏能否明确识别当前品牌、产品或对象？
- 是否存在一个服务内容的视觉锚点和记忆点？
- 只扫描标题、标签和数字能否理解页面？
- 每个区块是否只有一个职责？
- 卡片是否真的承担独立交互或状态？
- 动效是否改善层级、反馈或氛围？
- 去掉装饰阴影后，构图和排版是否仍成立？
- 换成另一项目名称后，页面是否仍然同样成立？若是，方向仍太通用。
