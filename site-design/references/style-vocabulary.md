# 按需求调用的网页风格词汇

本文件是**候选生成词汇**，不是模板目录。只在结构已确定、创作者需要比较多个风格且没有成熟设计系统或唯一明确参考时读取。先完成 [设计上下文](design-context.md) 的上下文账本与 [视觉方向](visual-direction.md) 的匹配画像，再从下面筛选适合的家族；不得随机抽取、按行业直接映射或复制示例品牌。

## 如何使用

1. 用匹配画像排除与受众、任务、素材、设备、无障碍或技术条件冲突的家族。
2. 保留 2～3 个**都合理但强调不同价值**的候选。差异应对应项目里的真实张力，例如效率与解释、权威与亲近、内容沉浸与快速判断。
3. 把家族翻译成项目自己的母题、色彩来源、字体角色、构图命题和细节签名。可以组合不同家族的机制，但每个被借用的机制都要服务一条不同需求。
4. 为每个候选记录移动/桌面适配、性能成本、无障碍风险、素材前提与实现复杂度；前提不成立且降级后会失去核心的候选直接排除。
5. 用同一结构、内容、状态和素材做成可比较页面；说明每个候选突出什么、牺牲什么，并给出推荐。

## 风格家族

| 家族 | 适合信号 | 核心视觉机制 | 前提与常见失败 |
| --- | --- | --- | --- |
| **机构瑞士 / Institutional Swiss** | 高信任、复杂信息需迅速建立秩序、品牌克制 | 严格栅格、清晰尺度、少量强调、精确对齐 | 需要强内容层级；失败时像空白模板或默认 SaaS |
| **人文出版 / Humanist Editorial** | 长阅读、教育、文化、研究、品牌需要温度 | 阅读型字面、刊物节奏、原文或实物成为主角 | 需要真实文本或素材；失败时变成米白加衬线的通用配方 |
| **大字编辑 / Typographic Editorial** | 观点、发布、媒体内容需要强入口 | 尺度反差、规则线、文字承担图像作用、节奏切换 | 需要短而有力的真实文案；失败时标题压过任务或中文排印粗糙 |
| **功能密集 / Functional Dense** | 高频处理、比较、监控、批量操作 | 紧凑网格、稳定行列、清楚状态、低装饰噪音 | 需要真实数据形状和状态；失败时压小字号或做成通用 Dashboard |
| **技术精密 / Technical Precision** | 开发者、基础设施、工程数据、可验证过程 | 等宽标识、发丝边界、结构化注释、受控暗色或中性色 | 技术内容必须真实；失败时无依据黑底发光、终端元素沦为装饰 |
| **实用文档 / Utility Documentation** | 文档、教程、分类发现、长内容导航 | 清楚目录、功能性色彩编码、代码或示例与正文并置 | 需要稳定的信息分类；失败时三栏骨架挤压主要阅读 |
| **实物画廊 / Object-led Gallery** | 摄影、器物、作品、场所本身有审美与判断价值 | 素材主导、界面退隐、克制说明、按内容变化的留白 | 依赖高质量且可授权素材；缺图时方向通常不成立 |
| **几何玩味 / Geometric Play** | 儿童、活动、轻消费、创意品牌需要亲近与反馈 | 原生几何、清晰轮廓、触感反馈、节奏性组合 | 必须符合受众与品牌；失败时像组件玩具或无关装饰 |
| **表现性粗野 / Expressive Brutal** | 文化、社区、实验产品允许冲突和直接表达 | 硬边界、强色块、非对称节奏、故意暴露结构 | 需要真实态度与文案支撑；失败时只有粗边框和硬阴影 |
| **档案复古 / Archival Retro** | 历史、收藏、地方文化、带时间感的技术或内容 | 档案编号、旧媒介比例、线描或印刷材料逻辑 | 需要真实年代或材料依据；失败时是假旧纹理和怀旧滤镜 |
| **电影化媒体 / Cinematic Media** | 音频、影像、演出、发布内容依赖时间与情绪 | 全幅媒体、时间节奏、少量强文字、状态与声音/画面联动 | 依赖真实媒体与性能预算；用渐变或假波形替代时通常失去核心 |
| **空间叙事 / Spatial Narrative** | 作品集、展览、旅程、时间线需要探索过程 | 滚动编排、空间关系、章节变换、位置驱动的发现 | 需要明确故事弧和输入方式；失败时动效拖慢任务或移动端失控 |

## 行业信号如何使用

行业只帮助召回可能影响视觉的**领域后果**，不直接选择风格。先在项目中验证这些后果是否存在，再进入匹配画像：

| 领域 | 优先核对 | 确认后可能影响 | 不能据此假定 |
| --- | --- | --- | --- |
| 技术与 SaaS | 使用频率、代码/数据形状、状态密度、键盘操作、响应速度 | 功能密度、技术精密、文档型表达 | 暗色、Bento、KPI、实时协作或固定 Dashboard |
| 金融 | 金额、风险、可逆性、审计、隐私、状态辨识 | 精确排版、克制运动、权威或功能型表达 | 深蓝金色、红绿作为唯一状态、实时行情或交易能力 |
| 医疗健康 | 压力情境、阅读能力、隐私、紧急程度、专业可信度 | 大字面、稳定层级、人文或机构型表达 | 蓝绿配色、柔拟态、评价背书、预约与用药能力 |
| 商业交易 | 实物判断、比较、价格、履约和交易是否属于范围 | 画廊、编辑或功能密集表达 | 购物车、支付、库存、倒计时、评价或促销紧迫感 |
| 本地与专业服务 | 地点、时间、资质、联系与预约是否属于范围 | 人文、机构或实用文档表达 | 预约系统、案例、前后对比、报价或地图集成 |
| 创意内容 | 作品、摄影、音频、视频及其许可和加载成本 | 画廊、大字编辑、电影化或空间叙事 | 重动效、全屏视频、作品集结构或暗色主题 |
| 生活方式 | 使用是否反复、数据是否私密、情绪负担、习惯反馈 | 人文、几何玩味或安静表达 | 粉彩、游戏化、连续打卡、社交证明或提醒能力 |
| 新兴技术 | 是否真的存在空间、实时、遥测、复杂模型或专业数据 | 技术精密、空间叙事或专门可视化 | 科幻 HUD、霓虹、3D、深色或实时监控 |

每条行业 cue 先分为 `within_scope | alternative_only | requires_confirmation | discard`。只有 `within_scope` 能影响当前候选；`requires_confirmation` 交给 `site-brief`，其余不能成为页面结构、功能或风格依据。尤其是任何命名功能、组件、页面段落和 CTA，都先视为待确认问题，不是行业“必备”。

## 调整轴

家族确定后，再由项目事实调整这些轴；轴不是额外风格，也不要求每个候选各占一档：

- **表达强度：** 大胆 / 中性 / 安静；
- **密度：** 紧凑 / 舒适 / 舒展；
- **材料：** 平面 / 线框 / 触感 / 摄影主导；
- **字体角色：** display / 阅读 / UI / 数据；
- **运动：** 静态 / 状态反馈 / 编排 / 沉浸。

具体颜色从品牌、真实素材或业务材料采样，具体字体按 [排版](typography.md) 的角色与可用性确定。家族名称、示例色和知名产品都不能作为采样来源。
