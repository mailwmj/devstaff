# 视觉候选比较词汇

本文件只帮助比较 `direction`，不选择 grammar 或 pattern。只有用户确实需要多个方向、且现有系统或明确参考没有给出唯一答案时读取；通常不必加载。

## 输入

先从任务合同与真实内容取出：内容主角、数量/形态、使用场景、用户先看/判断/操作什么、主要设备、已有素材与限制。行业名、规范名、模板 ID、配色和风格形容词都不能单独成为方向证据。

## 六个可观察轴

| 轴 | 要回答的问题 |
| --- | --- |
| 内容主角 | 哪个对象、原文、数据、实物或时间关系承担表达？ |
| 材料/媒介 | 主角属于纸张、档案、器物、地图、影像、仪表、对话还是其他真实世界？ |
| 构图 | 哪个内容最重，靠尺度、位置、留白、对比或顺序如何成立？ |
| 密度/节奏 | 用户是在连续阅读、快速扫描、反复操作还是探索？ |
| 字体角色 | display、标题、正文、UI、数据分别承担什么，不先指定字体品牌？ |
| 运动 | 哪个状态变化需要被解释；没有任务理由时保持静态？ |

这些轴是观察词汇，不是六套预制风格。一个方向只采用能由项目事实支撑的决定。

## 候选格式

固定同一任务、信息架构、真实内容、状态和素材，最多比较三个方向：

```yaml
direction:
  evidence: []
  motif:
  composition:
  project_signature:
emphasizes:
sacrifices:
conditions: []
```

候选必须在母题、构图或项目签名上有实质差异；只换颜色、字体或规范不算另一个 direction。每个形式决定都要说明帮助用户看见、判断或操作什么。

## 退出检查

- 替换项目名、行业与内容后仍完全成立：候选过于通用，继续推导。
- 去掉真实内容后页面几乎不变：主角选错。
- 只能用“高级、科技、杂志、电影感”等词解释：证据不足。
- 候选依赖尚不存在的素材或能力：记录条件并拒绝或降级。
- direction 成立后，再独立选择 grammar 与 patterns；不得反向用规范或模板补 direction。
