# 页面方向合同

这是体验稿或重大改版在首次视觉实现前使用的最小记录。它不是页面文案，也不是固定的页面结构；它把项目事实、方向判断和验证条件连接起来。

复制到项目的 `.site/design/surface-brief.md` 后填写。没有项目目录时，可以把它放在隔离体验稿目录中。

## 本轮问题

- **问题：** 本稿要验证什么？
- **工作类型：** `new-surface | redesign | existing-system | local-change | flow-state`
- **成果：** 结构候选（多个）、风格候选（多个）、单一方向，还是一个流程/状态演示？
- **结构候选数量：** 本轮让用户比较几个结构（`confirm-concept --structure-directions N`；只有一个时填 1）

## 设计推导

- **用户路径：** 用户先看什么、判断什么、做什么？
- **首屏命题：** 这页最先让用户理解的一个事实是什么？
- **真实素材主角：** 哪个对象、数据、文案或图片承担主要表达？
- **类别默认：** 如果按这个类别最常见的生成式答案来做，会是什么？
- **反默认原因：** 哪些项目事实要求不采用它？
- **替代结构：** 用什么信息拓扑、顺序、密度、强调或交互替代？
- **明确不做：** 本轮拒绝哪些页面、功能或视觉表达？

## 视觉方向（第二步的输入）

按 [视觉方向](visual-direction.md) 推导，每一条都要能说出从哪来。写不出母题来源时方向尚未形成，不要进入风格候选，也不要用配色或字体填空。

- **内容事实：** 哪一个对象、数据、文案或素材承担表达（去掉它这页还剩什么）
- **视觉世界：** 来自什么材料、媒介或环境；证据等级 `measured | derived | inferred`
- **母题：** 贯穿全页的那一个形式决定；换一个产品名是否还成立（成立＝不是母题）
- **色彩来源：** 从什么采样、收敛成哪些语义角色；见 [色彩与素材](color-and-material.md)
- **字体角色：** display / 标题 / 正文 / UI / 数据各用什么、为什么；见 [排版](typography.md)
- **构图命题：** 主次关系 + 它靠什么成立（尺度 / 位置 / 对比 / 留白 / 运动）
- **细节签名：** 哪一处做到 120%，它服务什么内容
- **素材与许可：** 来源、性质、许可、用途与裁剪；缺口有哪些

## 风格候选（第二步）

固定上面选定的结构、同一组内容和状态，只改变视觉方向。**结构选定后这一步必须做**，除非本轮只有一个结构、用户明确委托，或沿用已有成熟设计系统。

先按 [视觉方向](visual-direction.md) 形成匹配画像；需要扩展候选时读取 [风格词汇](style-vocabulary.md)。候选必须在**母题层**不同。填完表格后做交换检查：把任意两个候选的配色与字体互换，如果差异基本消失，它们就不是两个候选，回到上一步重新推导。

| 候选 | 匹配依据 | 母题 | 视觉世界 | 构图命题 | 突出 / 牺牲 | 实现 / 无障碍风险 | 结果 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| `甲` |  |  |  |  |  |  | `pending` |
| `乙` |  |  |  |  |  |  | `pending` |
| `丙` |  |  |  |  |  |  | `pending` |

- **交换检查结论：** 任意两候选互换配色与字体后，差异是否仍然成立？理由是什么？
- **行业 cue 分类：** `within_scope | alternative_only | requires_confirmation | discard`；行业名称本身不算上下文证据。
- **推荐项及理由：** 推荐不是确认，等待创作者选择。
- **候选不来自：** 无依据的风格标签、配方目录的相邻选项、同一母题的三种强度，或随机注入的大胆款。

### 使用边界

方向合同必须在第一次视觉实现前形成。无法写出项目特定的反默认和替代结构时，先补充事实，不要用 recipe、palette 或风格标签代替方向判断。**视觉方向一节写不出母题来源时，同样不得进入风格候选。** 结构确认和风格确认是两条记录、两句原话：只填了结构确认时，本稿没有完成，也不构成 `visual_confirmed`。
