# 设计约定与质量标准

本文件分两部分：**正向的质量判据**（质量由什么决定）和**负向的观察表**（哪些惯性答案值得怀疑）。两者都要用，不能互相替代——**只靠一张"不要做什么"的清单产不出好设计**，它只能挡住明显错误。

这些是缺少用户设计系统时的默认约定。用户要求、还原目标与成熟设计系统优先。token 和组件只能在方向形成后校准实现；完成度要看实际页面。

使用三种强度理解规则：

- **硬下限：** 真实性、主任务可达、基本可访问性、关键状态、中文可读和不伪造验证；适用时必须满足。
- **条件性风险：** 权限、支付、敏感数据、不可逆操作等只在首版已确认包含相应能力时生效，不能反向创造需求。
- **可覆盖启发式：** 构图、容器、密度、视觉表达和行业惯例；项目事实、成熟规范或有依据参考可以覆盖。

## 质量从哪来

四件事决定一个视觉方案是成品还是模板。每一条都必须能在实际渲染中指出来：

| 判据 | 成立的表现 | 不成立的表现 | 方法 |
| --- | --- | --- | --- |
| 方向有来源 | 能说出母题来自哪条业务事实；换一个产品名就不成立 | 只能说出风格形容词；换成任意产品都无损 | [视觉方向](visual-direction.md) |
| 字面成立 | 角色分配明确，字阶、行高、行长、标点与数字对齐无硬伤 | 多个方案只是同一组字体的不同字号；中文标题带负字距 | [排版](typography.md) |
| 材料真实 | 颜色有采样来源；素材有出处与许可；缺口如实显示 | 颜色凭空发明；色块冒充素材；通用素材图被当作内容证据 | [色彩与素材](color-and-material.md) |
| 构图有重心 | 缩小到 25% 仍有结构与重心；有一处服务内容的细节签名 | 缩小后是一团模糊；全页均匀用力，或大片留白配微弱元素 | [构图与节奏](composition.md) |

这四条不是打分，也不替代三路判断（设计 / 任务与状态 / 机械）。它们是**在设计判断这一路上要具体核对的内容**：写不出母题来源、字面有硬伤、素材来源不明或构图没有重心，都属于设计判断 `failed`，不能靠"任务能完成"抵消。

## 默认约定

- 先识别主任务、主要内容与主行动，让视觉重量与其对应。同一操作区域的主次按钮有清楚区分。
- 信息相关性决定分组；用留白、排版和分隔线建立层次，需要独立操作/选择/状态时才用容器卡片。数据比较优先列表/表格，阅读优先连续正文，作品优先素材。
- 中文 UI 默认使用稳定系统黑体栈；长阅读可用有中文回退的宋体标题或正文。中文标题默认正常字距，不照搬英文负字距和大写眉题。具体字阶与密度见 design-tokens.md。
- 留白服务阅读节奏和布局平衡。对空、少量和典型数量分别设计，不能靠假数据或大装饰填满空位。
- 颜色按语义角色使用，内容页控制强调色的分布；状态色附文字/图标，不只靠颜色。实际相邻文字、背景和控件边界需要检查。
- 同类控件有统一高度、边框与焦点规则。样式限制在组件作用域，避免全局 input 规则覆盖组合搜索框。原生控件和库组件同样要看最终渲染。
- 图标沿用同一视觉体系；真实图片用正确裁剪、比例和清晰度。没有封面时使用有设计的缺图状态，不把色块标成真实图片。
- 动效解释展开、切换、反馈等状态变化，尊重减少动态效果设置，不拖延主要操作。静态页面也可以精致。
- 窄屏重新组织导航、内容和主要操作；宽表可局部滚动，不能通过隐藏功能或支撑判断的价格、时间、状态、风险和解释来假装完成适配。少量数据不机械沿用多列卡片布局。
- 初次进入、正常使用、编辑、空/无结果、错误和保存结果，按真实可达状态设计；小型离线工具不用伪造网络加载。状态交互还要保持列表、详情、筛选、派生计数和未保存内容的一致，不能只让按钮可点。

## 识别常见“AI 味”：用观察代替风格禁令

| 常见表现 | 何时构成问题 | 对应改法 |
| --- | --- | --- |
| 巨大欢迎标题＋统计卡＋等宽卡片网格 | 各种工具都套同一结构，用户要做的事被挤到后面 | 用实际任务决定首页；先展示待处理内容、最近工作或主编辑区 |
| 紫蓝渐变、玻璃、发光边框遍布 | 无品牌或交互依据、层层抢注意力、降低可读性 | 收敛背景和强调区；品牌确实需要时保留在有作用的位置 |
| 所有内容都包进圆角卡 | 信息层级被相同容器压平，嵌套边框形成噪音 | 用列表、段落和对齐表达关系，只保留有独立含义的卡片 |
| 空泛口号、虚构增长数字、无依据评价 | 代替用户内容或暗示未经证明的能力 | 写清用户能做什么，示例显式标记，删去没有依据的证明材料 |
| 图标/Emoji 代替正文、封面与核心素材 | 用户难以识别内容，整页像占位稿 | 用真实内容与素材；没有素材时设计缺失状态 |
| 标题和摘要重复、到处英文小标签 | 消耗注意力却没有新信息，与中文产品语境不符 | 为每级文字安排职责，以自然中文组织内容 |
| 只给首页加装饰，编辑/弹窗仍粗糙 | 主任务界面与首页质量不一致 | 先完成代表操作界面，再传播组件与状态规则 |

不要仅因出现某个字体、渐变、蓝色或圆角判失败。类别标准有项目依据时可以采用；问题是无法说明来源、可被任意产品无损替换的惯性答案。每个发现都要说明位置、任务影响和修复方式；“不像 AI”不是可测量的验收结论。新建或重大改版还应检查：替换为惯用字体、常见配色或标准模板后是否几乎不影响表达，以及页面能否指出来自当前业务对象、真实内容或行为的项目特定表现。

## 实际验收

先查看选定依据与当前渲染。在任务相同、视口/内容/状态相近时比较，并按 [评审协议](review-protocol.md) 将三路证据分开：

1. 设计判断：按“质量从哪来”的四条逐项核对——方向能说出母题来源、字面成立、材料真实、构图有重心；主次区域比例与内容量匹配，留白有结构，而非只完成类别默认。
2. 任务与状态：能完成主要行动；操作后的列表、详情、筛选、计数、保存、取消和恢复语义一致。
3. 排版与素材：中文长标题、多段正文、数字和辅助文字可读，字体回退不破坏层级；标点、引号、避头尾、中西文混排与数字对齐符合 [排版](typography.md)；素材有出处与许可、裁剪正确、缺口如实显示。
4. 控件：检查搜索、表单、筛选、弹窗和核心动作的默认、焦点、选中、校验与保存反馈。
5. 内容：真实或标注示例的信息足够回答本稿问题；素材缺失、长内容、少量数据仍有诚实设计，不用模拟内容掩盖决策事实缺口。
6. 响应式：目标宽窄视口下主任务、主要行动及其必要证据可达，弹窗不遮住提交，导航/备份等功能有可见路径。
7. 一致性：代表页面和其他页面共用规则，最终结果兑现用户选定方向。

三路分别记录 `passed / failed / not_run / not_applicable`，附依据、页面/状态/视口、截图、具体发现及修复后的截图。截图存在不等于已审视；操作成功不等于视觉通过；无溢出不等于窄屏信息完整。还原稿与实现需要并置查看，区分条件不一致和真正偏差。

阻断主任务、明显结构失衡、偏离选定方向、重复套框、关键状态粗糙或窄屏功能丢失等主要问题，应修复并重新渲染后再交付为设计完成。细微偏好建议可单列，不无限打磨。能力缺失时标注未验证，不能补写通过记录。只读审查只报告，正式工程修复交给 `site-builder`。

## 校准示例

读书工具的书架能保存且无溢出，仍可能因为笔记藏在管理表单末尾而不符合“写作优先”。一本书占小卡片、重侧栏和空白占满屏幕，需要重新考虑少量内容构图。相反，如果用户选择藏书索引，规整列表可能比带大图的展示页更合适。

基准展示 `assets/design/gallery.html` 提供同一组中文业务内容、三个结构方案、三个示例风格和少量可点击反馈，用来演示"先结构、后风格"的两步流程以及变量替换的效果。它不是正式业务页面，也不是用户确认凭证；方向选定后仍需按实际项目内容、状态和视口重新检查，再由 `site-builder` 实施。

**不要把它当成合格风格候选的范例。** gallery 的三个示例风格靠替换 token（配色、字体角色、字号）产生差异，其中两个仍共用同一无衬线标题字族——按 [视觉方向](visual-direction.md) 的交换检查，它们接近"同一个方向的两种上色"。真实项目的风格候选必须在**母题层**不同，不能照抄 gallery 的做法。gallery 内嵌目录由 `design.py sync-gallery` 从 `tokens.json` 生成，`design.py validate` 会在两者不一致时失败。
