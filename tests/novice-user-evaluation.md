# 非技术创作者端到端评测

本评测用于维护和发布四个 Skill，不属于普通用户每次建站的操作。普通生成只自动执行轻量的真实渲染、核心任务和再次打开检查；只有 Skill 或资产升级时才运行本套固定回归。

## 画像与运行条件

评测者扮演没有编程背景、主要使用中文表达目标的创作者。他会描述现实任务、给自然反馈，但不会主动说出 Skill 名、状态机、技术栈或测试术语。

完整评测必须满足根目录 `AGENTS.md` 的预检和隔离要求：使用锁定的 `F-*` 副本；记录四个 Skill 的实际版本和哈希；由两名身份不同的真人独立操作；浏览器证据来自正式入口；Writer 冻结后 Checker 只读。条件不全时只能报告“主线冒烟/不完整”。

## 主线 UC

| ID | 用户目标 | 完成条件 |
| --- | --- | --- |
| UC-01 | 从模糊想法得到首个可验证版本 | Agent 只询问会改变任务或风险的未知，用户能用自然语言确认范围 |
| UC-02 | 在真实内容上选择结构和视觉 | 方向、样式语法、实现模式分别有依据；用户不需要理解内部术语 |
| UC-03 | 获得可运行成果 | 一条核心任务、错误恢复、目标视口和数据边界真实可用 |
| UC-04 | 关闭后再次使用 | 从交付入口重开，关键数据与说明一致，未验证项被如实说明 |

## 回归 RC

| ID | 必须观察的行为 |
| --- | --- |
| RC-01 | 新建项目从理解需求开始，不存在跳过确认的“快速新建” |
| RC-02 | 已知事实不重复提问，行业名称不创造产品能力 |
| RC-03 | 完整愿景与本轮范围分开保存 |
| RC-04 | 结构确认、视觉确认和开发授权不会互相冒充 |
| RC-05 | 局部修改和可复现 Bug 只走受影响路径 |
| RC-06 | `direction` 来源只能是 existing、reference 或 project-derived |
| RC-07 | `grammar` 独立记录 existing-system、packaged-spec 或 project-tokens |
| RC-08 | `patterns` 记录 selected、adaptations 和 rejected |
| RC-09 | 旧 `visual_source` 可读取但不会继续作为新模型写入 |
| RC-10 | 只有行业输入时语义选择返回 `needs_profile` |
| RC-11 | 硬约束先过滤，候选不超过三个且带理由和拒绝项 |
| RC-12 | 大师资料不进入风格候选 |
| RC-13 | 只读取最终选中的完整规范和实际使用的模板文件 |
| RC-14 | 模板在任务合同和方向之后选择，不带入未确认页面或字段 |
| RC-15 | 中文字体回退、标题字距和正文节奏在真实渲染上成立 |
| RC-16 | 参考的借鉴边界可回溯，不复制品牌和未确认功能 |
| RC-17 | 项目母题、构图和细节签名通过替换检查 |
| RC-18 | 外链 CSS、媒体查询和层叠后的 computed style 被实际检查 |
| RC-19 | 桌面和 390px 视口无不可解释的溢出、遮挡和过小触控目标 |
| RC-20 | 焦点、悬停、禁用、错误和加载状态有适用证据 |
| RC-21 | 图片能加载、替代文本存在，关键对象没有破坏性裁剪 |
| RC-22 | 核心任务按前提、操作、结果执行，而不是从代码推断 |
| RC-23 | 再次打开按真实交付入口验证，持久化失败不覆盖原数据 |
| RC-24 | 自动冒烟、人工视觉判断和完整回归结论明确分级 |
| RC-25 | 运行记录含版本、固定输入、模型/工具条件、选择/拒绝、产物、截图、得分、token、耗时、评测者、否决和 `not_run` |

## 评分

两名真人分别对五个维度打 `0..4` 分，并给出能改变判断的证据：

1. `task_scope_correctness`：核心任务正确，未扩张或漏掉已确认范围。
2. `direction_traceability`：方向、语法和模式均能回到事实与选择记录。
3. `project_specificity`：替换项目名称后，关键表达不能无损复用。
4. `visual_craft`：排版、材料、构图、状态和跨视口细节达到可交付水平。
5. `state_mobile_reopen_resilience`：错误、移动端、中途退出和再次打开可靠。

完整分级只在全部 UC、RC、SD、MV 都执行且无非计划 `not_run` 时计算：平均分 `>=3.5` 为 A，`>=3.0` 为 B，`>=2.0` 为 C，其余为 D；任一核心任务失败、维度为 0 或触发否决项，最高只能是不通过。

## 否决项

- 越过确认或开发授权；
- 让规范、行业或模板创造未确认能力；
- 没有真实渲染却宣称视觉或交互通过；
- 核心任务失败仍交付；
- Checker 修改冻结源码；
- 伪造用户原话、素材、截图、token、评测者或测试结果；
- 用同一人、模型或 Agent 的两次运行冒充两名真人。

## 运行记录

以 `tests/evaluate.py` 校验 JSON。普通自动冒烟可以只有一个 `automated` 评测者，但必须保持 `evaluation_complete=false`；完整单场景记录使用：

```sh
python3 tests/evaluate.py validate-catalog
python3 tests/evaluate.py validate-run path/to/run.json
python3 tests/evaluate.py validate-run path/to/run.json --full
python3 tests/evaluate.py compare before.json after.json --target 0.30
```

`--full` 对一条记录分别返回：`evaluation_complete` 表示两名真人和证据均齐全，`release_ready` 表示核心任务、五维得分和否决项同时达标。完整但失败的基线仍可比较。`compare` 只接受前后各 25 个固定场景，并核对相同 suite、固定输入、模型和工具条件；最终人工责任仍按 `AGENTS.md` 执行。
