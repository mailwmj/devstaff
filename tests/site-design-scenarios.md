# 设计质量固定场景

场景输入和夹具的机读权威是 `tests/scenarios.json` 与 `tests/fixtures.lock.json`。本文件说明评测方式，不重复保存完整输入。

## SD-01～SD-17

| 范围 | 重点 |
| --- | --- |
| SD-01～SD-08 | 中文内容、材料图片、数据工作区、本地 CRUD、表单恢复、参考驱动、已有项目改版、复杂移动流程 |
| SD-09～SD-11 | 行业不能直选、方向/语法分层、模板只能在任务合同之后选择 |
| SD-12～SD-15 | 中文字体、素材硬约束、无命中弃权、大师方法隔离 |
| SD-16～SD-17 | 外链 CSS 的 computed style、项目特异性替换检查 |

每个 SD 场景都检查五条证据链：固定输入没有被改写；候选及拒绝原因可见；最终 `direction / grammar / patterns` 可追溯；真实成果完成核心任务；视觉与项目事实之间存在不能由通用模板解释的联系。

## MV-01～MV-08

| ID | 视口/状态 | 通过依据 |
| --- | --- | --- |
| MV-01 | 390px 中文阅读 | 无遮挡与横向溢出，目录和返回路径可用 |
| MV-02 | 390px 表单错误 | 焦点、汇总、字段关联和输入保留成立 |
| MV-03 | 390px 数据比较 | 关键数据不被隐藏，重排或受控滚动可用 |
| MV-04 | 单手连续操作 | 核心触控目标至少 44×44，布局不跳动 |
| MV-05 | 极端中文内容 | 长标题、长段落和标点不破坏容器 |
| MV-06 | reduced motion | 非必要长动效停止，任务仍成立 |
| MV-07 | 错误/禁用/加载 | 状态有语义并且不只靠颜色表达 |
| MV-08 | 再次打开 | 从交付入口重开，数据和限制与说明一致 |

## 证据纪律

`check-output.mjs` 只是静态规范预检；渲染机械证据来自 `check-render.mjs`。自动检查可判 computed style、字体声明、对比度、溢出、触控尺寸、图片加载/裁剪和合同化操作，但不能判定构图是否有重心、方向是否真正属于项目。后两项由两名真人分别查看桌面与手机实际页面后评分。

每个自动探针都必须在 `render-good` 与 `render-bad` 控制页上证明“该过时过、该失败时失败”。新增规则时同步新增正反控制，不允许只增加一个永远为绿的检查。
