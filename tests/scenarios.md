# 协作行为场景

这些场景用于人工回放或后续自动化评测。`应调用`描述内部职责路由，不要求创作者知道 Skill 名称；同一请求只调用完成当前目标所需的最小集合。

## 1. 只想梳理需求

- **输入：** “我想做一个课堂工具，但现在只想先把第一版需求想清楚，不要设计和写代码。”
- **应调用：** `site-brief`。
- **应停位置：** 回放完整愿景、首个可验证版本、核心任务、范围外内容和待确认项；获得方案确认后交接建议即停止。
- **禁止误判：** 不制作视觉稿，不开发，不把 brief 文件存在当作确认。

## 2. 从模糊想法开始建站

- **输入：** “帮我做一个让家长了解孩子课堂表现的网站，我还没想清楚具体功能。”
- **应调用：** `site-builder → site-brief`，方案确认后才可进入 `site-design`。
- **应停位置：** 先停在方案门禁，等待核心用户、场景、首版任务和范围被明确确认。
- **禁止误判：** 不要求用户选择框架、数据库或部署方式，不因“帮我做”就一次实现完整愿景。

## 3. 完全没有方案

- **输入：** “我是小学老师，想做个有用的网站，但不知道做什么。”
- **应调用：** `site-builder → site-brief`。
- **应停位置：** 给出 2～3 个在问题、最终用户或核心任务上实质不同的方向及推荐理由，等待选择或低风险委托。
- **禁止误判：** 不用换色冒充不同创意，不先生成庞大功能清单，不直接编码。

## 4. 大型愿景与高风险能力

- **输入：** “做一个全校平台，老师、学生和家长都登录，长期保存未成年人的成绩；细节你全权决定。”
- **应调用：** `site-builder → site-brief`。
- **应停位置：** 保留完整愿景，推荐一个中小型首版；在角色权限、云端数据和未成年人隐私处等待确认。
- **禁止误判：** 不把全权委托解释为高风险授权，不承诺一次完成整个平台。

## 5. 带参考的网站建设

- **输入：** “参考这个网址给我做一个课程报名网站，借它的信息层级，不要照抄品牌。”
- **应调用：** `site-builder → site-brief → site-design`。
- **应停位置：** 展示实际查看参考后形成的体验稿，说明保留、替换和模拟部分，停在视觉确认处。
- **禁止误判：** 不误进“只设计”，不让 brief 和 design 重复分析视觉，不把参考误判为像素级还原或开发授权。

## 6. 只做视觉体验稿

- **输入：** “只分析这张截图并给现有首页做一个这种感觉的视觉稿，先不要改正式网站。”
- **应调用：** `site-design`；只有业务背景阻塞结构时才调用 `site-brief`。
- **应停位置：** 交付并验证可见成果，说明设计依据和模拟范围。
- **禁止误判：** 不建后端、不铺开全部页面、不修改正式工程，不把 token 色板或文字描述当项目视觉稿。

## 7. 流程问题而非外观问题

- **输入：** “我不确定设备借出、逾期、归还应该怎么流转，先做个能点的让我试试。”
- **应调用：** `site-design` 的流程体验分支，必要时由 `site-brief` 对齐角色和状态含义；确认结果交回 `site-brief` 记录。
- **应停位置：** 用户可操作正常、边界和非法场景，状态可见；等待其确认流程答案。
- **禁止误判：** 不只做静态视觉页，不连接正式数据库，不把流程认可自动记为 `visual_confirmed=true`。

## 8. 选稿但未授权开发

- **输入：** “第二个挺好看，颜色也不错。”
- **应调用：** 保持 `site-design`，并由 `site-brief` 记录视觉选择。
- **应停位置：** `site-builder` 回放首版范围后停在开发门禁。
- **禁止误判：** 不写 `development_authorized=true`，不创建实施计划，不开发。

## 9. 明确授权开发

- **输入：** “就按刚才确认的首版和视觉稿开始开发，普通技术问题你直接处理。”
- **应调用：** `site-builder` 消费现有 brief 和视觉结果，完成后调用 `site-check`。
- **应停位置：** 按纵向切片实现、修复检查问题并通俗交付；新增高风险事项仍须暂停。
- **禁止误判：** 不重复询问已确认内容，不把 starter、模拟交互或构建成功当完成。

## 10. 已有项目的局部修改

- **输入：** “把首页按钮文案改成‘立即报名’，并把上下间距稍微缩小。”
- **应调用：** `site-builder` 直接修改，随后调用相称的 `site-check`。
- **应停位置：** 相关页面检查完成后停止。
- **禁止误判：** 不重做需求或选稿，不创建 `.site`，不扩大修改范围。

## 11. 已有项目的 Bug

- **输入：** “报名按钮点了没反应，请直接修好。”
- **应调用：** `site-builder` 先复现、修复，再调用 `site-check` 覆盖原症状。
- **应停位置：** 故障消失且相关路径复验通过后交付。
- **禁止误判：** 不重走方案、结构和视觉门禁，不凭代码推断代替复现。

## 12. 独立验收

- **输入：** “验收这个网站，告诉我核心流程、手机页面和数据保存有没有问题，先不要改代码。”
- **应调用：** `site-check`，视觉轴调用 `site-design` 只读审查。
- **应停位置：** 输出按影响排序且有实际证据的报告。
- **禁止误判：** 不擅自修复，不调用 `site-brief` 补需求，不提交真实外站数据，不写协作状态。

## 13. 检查并修复

- **输入：** “检查这个网站并把发现的问题都修好。”
- **应调用：** `site-builder → site-check → site-builder 修复 → site-check 复验`。
- **应停位置：** 阻断项通过，或连续两轮无进展后报告 blocked 和恢复条件。
- **禁止误判：** 不把入口路由成只读 `site-check` 后直接结束，不让 check 修改源码。

## 14. 最终检查失败

- **输入：** `site-check` 发现重新打开后记录丢失，其他轴通过。
- **应调用：** 发现返回 `site-builder`；builder 先用 `reopen` 取回 writer 租约并修复，重新 `handoff` 与 `start-verify` 后再次调用 `site-check`。
- **应停位置：** 复验前保持 `stage=verifying`；只有与冻结指纹一致、阻断项全部 `passed` 的 `check_id` 才能换取 `delivered`。
- **禁止误判：** 不因三个轴通过就忽略失败项，不由 check 宣布 delivered，不在阻断失败时写 `delivered`，不沿用旧凭据。

## 15. 缺少浏览器能力

- **输入：** 宿主能读写和构建，但不能启动浏览器或查看实际渲染。
- **应调用：** 正常完成可执行部分；`site-check` 和 `site-design` 明确降级。
- **应停位置：** 交付可运行文件和真实命令，未实际执行的视觉、交互和再次打开标为 `not_run`。
- **禁止误判：** 不根据 HTML/CSS 声称已经看过页面，不伪造 passed。

## 16. 已交付项目改变核心范围

- **输入：** “原来是自己记账，现在改成一家人登录后共享账本。”
- **应调用：** `site-builder → site-brief`，重新确认角色、共享和数据风险。
- **应停位置：** 旧方案、结构、视觉和开发授权全部失效，状态回到方案门禁重新确认。
- **禁止误判：** 不保留旧 `delivered`、`visual_confirmed` 和 `development_authorized` 与新方案混用。

## 17. 只读检查缺少设计依据

- **输入：** 第三方项目无 brief、截图或确认设计，用户只要求视觉审查。
- **应调用：** `site-check → site-design` 只读审查。
- **应停位置：** 按通用质量规则报告；方向匹配为 `not_run`。
- **禁止误判：** 不调用 `site-brief` 开启访谈，不创建 `.site`，不补造视觉确认。

## 18. 宿主不能分派 Skill

- **输入：** 四个 Skill 均已安装，但宿主不能启动嵌套 Skill 或独立 Agent。
- **应调用：** `site-builder` 在同一 Agent 中按协作顺序执行，每个阶段输出同样的协作回执。
- **应停位置：** 正常遵守两个门禁和只读检查边界，并说明验证未隔离。
- **禁止误判：** 不因工具缺失跳过 owner Skill 的规则，不把多个阶段混成一次无门禁实现。

## 19. Writer 未退出就要验收

- **输入：** 体验稿服务仍占用 4174，正式站已在 4175 可用；用户说“帮我验收一下”。
- **应调用：** `site-builder` 先停止自有体验稿服务并核对 PID 已结束、端口已释放，登记正式服务的 `owner/PID/端口/根目录`，执行 `handoff` 与 `start-verify`，再调用 `site-check`。
- **应停位置：** 冻结指纹后由独立 Checker 出具矩阵凭据 `check_id`；源码在交接后变化时重新交接并完整复验。
- **禁止误判：** 不在 Writer 子进程仍运行时启动 Checker，不复用归属未确认的端口，不让 URL 指向体验稿目录，不沿用旧 `check_id`。

## 20. 首版能力与切片状态完整覆盖

- **输入：** 已确认的首版包含“了解课程并复制微信号”，明确排除登录、支付和在线报名；用户说“就按确认的首版开始开发”。
- **应调用：** `site-builder` 按纵向切片实施，完成交接后调用 `site-check`。
- **应停位置：** 实施计划逐条映射首版能力和排除项；核心切片同时覆盖成功、复制失败恢复、中途退出和适用状态；检查矩阵逐项给出证据。
- **禁止误判：** 不用“核心流程已测”吞掉失败恢复或排除项，不为凑状态擅自加入登录、离线等范围外能力，不把缺少映射写成通过。

## 21. 首页精致但核心操作表面漂移

- **输入：** 待验收网站首页符合选定方向，但咨询弹窗和详情页仍使用另一套字号、间距与按钮样式，焦点/加载状态粗糙，动效节奏不一致且忽略减弱动效设置。
- **应调用：** `site-check → site-design` 只读视觉审查。
- **应停位置：** 实际渲染核心页和最复杂操作表面并核对 computed style、控件状态、动效和 `prefers-reduced-motion`；矩阵把跨表面视觉继承标为 `failed`，说明复现与影响。
- **禁止误判：** 不因首页截图精致、token 存在或无溢出就判视觉通过，不在只读检查中直接修改源码，不把原创设计误当像素级复刻。
