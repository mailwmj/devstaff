# 首版梳理与协作记录

## 协作契约

交接或恢复会话时读 [上下文契约](references/context-contract.md)。术语与确认模型以 [领域术语](../CONTEXT.md) 为准，状态写入、原话归属、租约和拒绝条件以 [状态协议](references/state.md) 为准；本 Skill 不复制这些协议。

| 字段 | 本 Skill 的接口 |
| --- | --- |
| `reads` | 最新请求、项目事实、`.site/brief.md`、`state.py show`；缺少材料只补阻塞首版的未知 |
| `writes` | `.site/brief.md`；状态与恢复快照仅由 `state.py` 写入 |
| `schema` | `ready / needs_user / blocked`；内容区分事实、决定、假设、首版切片、包含、排除与风险 |
| `handoff` | `ready` 返回调用者或建议下一 Skill；不代表视觉确认或开发授权 |
| `evidence` | 可定位的项目事实、查证来源和用户原话记录；无法查证的内容保留为假设 |

## 选择分支

- **梳理首版：** 执行下面的 1～7 步。
- **记录协作结果：** 其他 Skill 已完成其职责内判断时，只执行第 6 步；不重开需求访谈，也不替调用者改变结论。

## 执行

1. **恢复上下文。** 读取用户材料、现有 brief、状态和相关工程事实，区分事实、决定、假设与待确认；冲突保留差异。
2. **找到当前前沿。** 读 [需求发现](references/discovery.md)，只询问会改变核心任务、体验边界或风险的问题；依赖外部事实时按 [轻量研究](references/research.md) 查证。
3. **检验理解。** 对业务词冲突先对齐含义，再用具体场景回放“谁在什么情况下做什么、看到什么结果”，必要时补边界场景。
4. **收敛首版。** 保留完整愿景，推荐一条可完整体验的核心任务，明确结果、包含、暂不包含、风险和剩余假设。
5. **增量记录。** 按 [brief 规则](references/brief.md) 更新 `.site/brief.md`；需要状态跃迁时只调用 [状态协议](references/state.md) 的工具，不直接编辑状态文件。确认记录必须使用当时回答该决定的用户原话；结构确认和视觉确认按状态协议分别处理。
6. **确认并交接。** 回放完整愿景、核心用户与场景、首版任务、范围、假设和风险，明确当前只确认首版方案。没有得到这项决定就继续澄清，不借后续阶段的肯定答复倒填。
7. **停止。** 输出协作回执后停止，不制作体验稿、实施计划、依赖或业务代码。

## 协作回执

返回：项目、`ready | needs_user | blocked`、本轮新增/变化的事实与决定、被更新的记录、仍未确认的高风险项、建议下一 Skill。`ready` 只表示首版方案已确认。
