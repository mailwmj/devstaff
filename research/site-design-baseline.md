# Site Design 0.4.0 基线回放

> 日期：2026-09-11  
> 方法：四个生成子 Agent 使用仓库当前 `site-design/SKILL.md` 与 references 完成隔离体验稿；两个独立评审 Agent 只读取产物和截图；另以范围防火墙、无依据只读审查测试边界。测试产物位于 `/tmp/site-design-baseline/`，不作为仓库交付资产。

## 1. 总结

当前版本并非整体失效。它已经能稳定做到：使用真实或标注示例内容、控制范围、生成可见成果、制作结构不同的候选，并在多个视口实际检查。早餐车看板尤其证明，模型在任务事实具体时能产生明显超出通用 Dashboard 的业务结构。

主要缺口集中在四处：

1. **展示前自评偏完成性，未稳定发现真实 UX 缺陷。** Agent 均报告目标视口 `passed`，独立评审仍发现关键证据被隐藏、移动裁切、编辑一致性和未保存数据问题。
2. **设计方向缺少项目特定反事实。** 课程页虽有自然观察视觉世界，但宏观结构仍是标准营销长页；博物馆三方向部分依赖“海报 / 决策卡 / 报刊”现成风格范式。
3. **结构与状态之间缺少语义一致性检查。** CRM 能交互，但保存后 tab 数量与筛选范围不会重算，切换联系人会静默丢弃未保存内容。
4. **未知事实虽被诚实标记，仍可能被模拟内容填成看似完整的页面。** 课程日期、时长、集合、安全、陪同和取消规则缺失时，页面仍铺开完整营销结构和四次课程细节。

因此本轮不需要复制大规模行业模板；优先补强“项目事实 → 方向 → 结构 → 状态 → 实际评审”的闭环。

## 2. SD-01 个人 CRM

### 当前表现

- 以“今天先联系 7 人”为首页任务，没有先放 KPI 卡片。
- 桌面采用列表与详情并列，手机使用列表与全屏详情。
- 未增加登录、团队、权限、同步、报表或自动化。
- 生成者报告 1440 与 390 视口、核心交互和控制台均 `passed`。

### 独立评审发现

- 需求适配 5/5、UX 4/5、视觉完成度 4/5、项目特异性 4/5；AI 模板感 3/5。
- 保存只更新日期和字段，不重算 `scopes`；标题和 tab 数量仍是静态值。
- 切换联系人会直接覆盖表单，没有 dirty-state、确认或自动保存。
- 手机详情中来源值被挤掉；原型说明条占据窄屏空间。

### RED 证据

当前“检查核心交互”容易停在按钮可点和字段可写，没有验证操作后列表、筛选、计数和未保存状态是否保持业务一致。

## 3. SD-02 课程落地页

### 当前表现

- 首屏呈现地点、年龄、次数、价格、人数和微信 CTA。
- 使用西溪湿地、观察手记、白鹭与水纹建立视觉世界。
- 没有伪造 Logo、评价、报道、教师照片或二维码。
- 生成者报告桌面、手机、弹窗、焦点、对比度和无横向溢出均 `passed`。

### 独立评审发现

- 需求适配 4/5、决策效率 3/5、视觉完成度 4/5、项目特异性 3/5；AI 模板感 4/5。
- 宏观结构是常见的导航＋双栏 Hero＋事实条＋价值解释＋课程列表＋教师＋适合谁＋FAQ＋末尾 CTA。
- 日期、时长、集合、陪同、安全与取消规则缺失，微信终点也不可执行，尚不能完成真实报名判断。
- 手机截图中正文、主视觉和固定 CTA 出现右侧裁切迹象，与自报 `passed` 冲突。

### RED 证据

当前规则能阻止造假，却未要求区分“视觉稿足够判断”与“页面看起来完整但关键决策事实缺失”；展示前自评也没有可靠捕获核心 CTA 的窄屏问题。

## 4. SD-03 早餐车备货看板

### 当前表现

- 首屏先给“今天备多少、首批多少、何时补”，历史数据位于第二层。
- 天气、昨日余量、售罄和高峰形成具体决策链。
- 模拟的建议量与用户提供事实明确区分。
- 独立评审认为不是通用 Dashboard 换文案：需求适配 5/5、UX 5/5、项目特异性 5/5，AI 模板感 2/5。

### 独立评审发现

- 768px 直接隐藏降雨解释和“建议怎么来的”，删除了建议可信度所需信息。
- 页面更像优秀决策简报，未提供确认、调整或雨势复核操作；是否需要这些能力应由体验稿问题决定。
- 缺少数据过期、天气失败、历史缺失或人工覆盖等状态。

### RED 证据

当前 `design-quality.md` 已写“窄屏不能隐藏功能”，但规则不够靠近验证动作，Agent 仍以简化为由隐藏了决策关键证据。

## 5. SD-04 博物馆三方向

### 当前表现

- 三稿使用相同内容并提供稳定查询参数。
- A 为展览海报、B 为周末决策、C 为社区周刊；B 的时间、地点和三件事均在首屏，推荐与移动决策任务一致。
- 独立评审确认三者有结构差异，结构差异 4/5。

### 独立评审发现

- A 与 C 去除字体、色彩和风格语言后，仍共享“主展优先、两项活动其次、实用信息收尾”的骨架。
- 三种方向本身对应常见 AI 视觉范式，差异部分来自风格标签而非项目事实。
- 缺真实馆名、馆藏、日期、场次和参加条件，项目特异性为 3/5。

### RED 证据

当前规则阻止“只换色”，但尚未阻止使用现成风格类型替代更深的业务推导，也没有 swap/signature 检查。

## 6. 边界场景

### 非交易型陶器目录

Agent 明确拒绝朋友提出的标准购物流程，只设计目录、筛选、详情、缺图、无结果和复制微信号；被排除能力没有泄漏。范围防火墙在输入明确时已经表现良好。

### 无依据只读审查

Agent 返回 `review_complete`，未修改文件、未创建 `.site`，并把方向匹配和跨页一致性标为 `not_run`。当前只读边界可保留。

## 7. 本轮最小改进目标

1. 在新建或重大改版前形成简短、项目特定的方向合同；局部修改和成熟设计系统跳过。
2. 明确类型知识只能召回问题、状态和条件机制，不能证明新范围。
3. 多方向增加反默认、swap 与项目标志检查，不以现成风格标签充当结构差异。
4. 验证拆成设计判断、任务/状态和机械检查；展示前必须根据实际渲染修一轮。
5. 状态体验检查操作后的派生数据、筛选、计数、未保存内容和恢复，而不仅是控件可点。
6. 窄屏逐项核对主任务、主要行动及其必要证据，不允许通过隐藏来通过检查。
7. recipe 明确为实现校准工具，不是方向或确认凭证。
