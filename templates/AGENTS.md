# 渐进式建站：路由与门禁

用户是非技术中文创作者，只描述目标、参考、现有项目和反馈。你负责选 Skill，不让他选择阶段、模式或技术栈。新建没有快速分支；局部修改只按影响缩短路径。

## 处理顺序

1. 读取工程说明和 `.site`；有状态时先运行 `site-brief/scripts/state.py show`，取得门禁、租约和冻结状态。只用对应工具写 `.site/state.json`、租约和检查凭据。
2. 用一句普通话说明本轮动作和决策点，按下表进入一个 Skill，并完整执行其 `SKILL.md`。协作回执不展示给用户。
3. 交付先给真实入口和可执行动作，再说范围、数据位置、限制与未运行项；不使用内部术语。

## 入口路由

| 用户目标 | 入口与停位 |
| --- | --- |
| 新建、整体改版、改变主流程/导航/信息结构 | `site-builder` 编排完整流程；按未通过的决定停下，不存在快速新建 |
| 明确只梳理需求或说“先不要做” | `site-brief`；交付方案回执后停止，不制作体验稿或业务代码 |
| 看效果、分析参考、做体验稿或只读设计评审 | `site-design`；正式源码只读，视觉确认不自动授权开发 |
| 只检查/验收，没有要求修复 | Writer 已退出且源码已冻结时进入 `site-check`，否则先由 `site-builder` 交接；Checker 停在报告 |
| 检查并修复、修 Bug、改文案/样式/局部行为 | `site-builder`；只处理受影响范围，修复后重新冻结和复验 |
| 继续上次工作 | 先读取状态，从下一项未满足的决定或检查恢复 |

无 `.site` 时，仅新建/整体改版初始化状态；局部修改、可复现 Bug 和第三方只读审查不创建。只读评审不补造依据，缺失判断记 `not_run`。

## 红线

1. `concept_confirmed=false`：不正式设计或开发；规范、行业和模板不能创造需求。
2. 结构、视觉、开发授权分别判断。只选页面组织时只记录结构；视觉称赞不是授权。持续建设委托只在前置决定已确认且范围未实质变化时有效。
3. 只有当前源码的 `site-check` 矩阵阻断项全过，且交付入口/再次打开已验证，才能交付。构建、文件或截图不能替代核心任务。

核心用户、任务、范围、结构或风险边界变化时，按 `site-brief` 的 `reopen --scope-changed` 使旧结论失效。费用、系统安装、第三方授权、敏感数据和公开部署逐项取得当下授权；全权委托不覆盖。

确认记录保存用户原话但不证明同意；按 `site-brief` 记录证据等级，交付时回放。用户否认即重新确认。

## 能力降级

- 无独立 Checker：同一 Agent 串行执行并说明“验证未隔离”。
- 无浏览器或命令能力：对应项为 `not_run`，不能从源码推定通过。
- 连续两轮修复/复验无新证据或进展：由 `site-brief` 记录阻塞和恢复条件。

项目可以追加团队路由，但不得放宽上述红线；冲突时以四个 `site-*` Skill 和状态工具为准。
