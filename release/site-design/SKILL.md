# 网站设计

设计能力完整保留，流程按需加载。目标是用项目事实形成有辨识度、可实现、可验证的方向，不是套模板，也不是让用户学习设计流程。

## 先选分支

| 任务 | 产出 | 怎么读 |

| 成熟系统中的局部页面或样式修复 | 继承基线和最小修正，不重做设计系统 | [设计上下文](references/design-context.md) ➔ [工艺审查](references/craft-review.md) |

## 按步骤读，不要一次读完

前两个分支各自涉及的文件合计约 64KB。**不要预读整组。** 按下面的序列推进：每步只读该步列出的文件，做完这一步再读下一步。一次读完不会让判断更准，只会把注意力从当前这一步稀释掉（下面每步的体量是实测值，单步最大 18KB）。

[页面设计合同](references/surface-brief.md)（16KB）是全程的填写目标：在 A1 开始时打开一次，之后每步只填对应小节，不要重读全文。它是填空骨架，字段值一律写本项目的事实，不照抄骨架里的说明句。

## 默认工作法

1. 先看活跃工程、真实内容、品牌、素材和明确参考；缺失事实才调用 `site-brief`。
2. 写出使用者、主任务、业务对象、真实内容、关键状态、设备和风险。
3. **信息架构双选**：用通俗易懂的大白话提炼 2 种高区分度架构方案（说明适合谁、第一眼看到什么、怎么操作），同时轻量快速生成单文件骨架预览页（纯灰阶布局、顶部带切换），给出文件链接并优先引导在 Agent 客户端自带浏览器打开。
4. **视觉风格双选**：骨架选定后，在同一骨架上提供 2 种视觉气质差异鲜明的方案，生成轻量静态视觉预览单页（双风格无感切换）。严格坚守轻量：不写复杂业务逻辑代码，不执行单元测试、合同校验及全套浏览器深度断言。
5. **微调收敛与资产平滑继承**：支持用户在视觉 Demo 上快速提出微调偏好（单页 HTML/CSS 即时响应）；用户确认满意的 Demo 直接作为正式代码胚胎——提取 CSS 变量沉淀为正式 Token，提取核心 HTML 作为第一条纵向切片的模板，微调诉求沉淀为 `VA-*`。
6. 用户确认完整方向后，`site-builder` 用一次 `decide` 记录，正式进入构建循环。
7. 在 `.site/design/surface-brief.md` 中只填写本轮适用字段，交回实现和检查。

## 设计资产

- `assets/design/`：Token、gallery 和基础样式。
- `scripts/design.py`：设计系统检索、Token 构建和资产校验。
- `intelligence/`：内置检索数据与 MIT 许可代码。
- `references/`：上下文、方向、落地页指南、体验稿、参考输入、Token、工具链、中文排版规范、页面设计合同和工艺审查。

## 硬约束

- 行业、竞品、模板和检索结果不能创造首版功能。
- 配方和色板只校准已形成的方向，不能代替方向。
- 实际查看才算验证；文件存在、构建成功或截图存在都不能单独证明设计成立。
- 素材记录来源、许可、裁剪和 alt；缺失时诚实呈现。
- 方向确认前不修改正式业务源码；流程体验稿不连接正式数据库。
- 体验稿与视觉预览阶段坚守轻量边界，不堆砌业务逻辑代码，不跑重度测试套件；不承诺"秒级生成"等绝对速度。

使用五字段回执 `status / summary / artifacts / evidence / limitations` 返回一次，然后停止。
