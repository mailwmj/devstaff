# 落地页与营销转化设计指南

本文件是 `site-design` 与 `site-brief` 在面对**落地页（Landing Page）、产品营销页、官网首屏及单目标转化页面**时的专项领域参考。

落地页不是应用程序（Web App），也不是承载泛化意图的综合门户（Portal）。它的第一性原理是**单一心智说服与注意力转化**：

$$\text{One Offer} \longrightarrow \text{One Audience} \longrightarrow \text{One Primary Action}$$
**一个明确承诺 $\longrightarrow$ 一个核心受众 $\longrightarrow$ 一个首要行动**

---

## 1. 适用范围与定位

- **适用**：产品落地页、SaaS 官网、活动报名页、Waitlist 收集页、资源下载页、单品发售页。
- **不适用**：B 端后台管理系统、多状态复杂应用、数据看板（Dashboard）、工作台。此类场景遵循标准 [页面设计合同](surface-brief.md) 与 [任务交互合同](design-context.md)。
- **核心目标**：抓取第一注意力、建立信任、拆解顾虑、消除风险、促成转化。

---

## 2. 需求收敛模型（Landing Page Brief）

当任务判定为落地页时，无需按通用应用探究复杂的数据库、多端同步或权限角色，优先收敛以下四项核心事实：

1. **唯一首要行动（One Primary Action）**：
   - 什么是本页唯一的转化定义？（例如：免费注册、预约 Demo、加入等候名单、立即购买、下载手册）。
   - 严禁在首屏放置互相争抢注意力的并列主操作。
2. **核心承诺与交付物（The Offer）**：
   - 用户到底能得到什么确定性价值？（强调结果与收获，而非抽象技术）。
3. **受众与认知上下文（Audience & Context）**：
   - 谁是核心客户（ICP）？
   - 流量从何而来（广告、搜索、社交媒体、私域邮件）？
   - 访问者进入页面前已经知道了什么？承接上下文，保持承诺一致。
4. **三大决策顾虑（Top 3 Objections）**：
   - 用户今天为什么不转化？（太贵、学习成本高、怀疑效果、迁移困难、担心安全与退款）。
   - 每一个主要顾虑，必须在中段或尾部有专门的结构或证据予以反击。

## 3. 页面标准说服结构（12 段式骨架）

落地页的信息架构遵循心理学说服链路，从上至下分为三幕：

### 第一幕：首屏注意力与承诺（Above the fold）
1. **主标题（Headline）**：直击结果与受众，3 秒内看懂（见文案公式）。
2. **副标题（Subheadline）**：解释如何实现，补充具体性，消除模糊感。
3. **首要行动（Primary CTA）**：动词 + 用户获得物（如“免费开始 14 天试用”）。
5. **视觉主角（Hero Visual / Anti-Slop 资产规范）**：
   首屏视觉侧是建立专业感的核心，按以下优先级三选一，严禁空洞的渐变发光紫斑或纯色占位符：
   - **优先级 1（真实资产）**：具备生图工具时，生成真实高精度的产品场景、实物摄影或真实截图；
   - **优先级 2（手艺标准：高保真迷你组件预览）**：无外图时，手写真实高保真组件片段，必须满足：
     * **物理深度 $\ge$ 3 层**：窗口壳/微阴影外框 + 主业务操作界面 + 悬浮状态元素（浮动通知徽标、操作气泡、光标轨迹），层层错落并带有明确投影；
     * **信息密度 $\ge$ 8 项真实元素**：真实微文案、有机业务数据、真实头像、具体时间戳与状态点，坚决消灭空心矩形与三条灰线的“div 假截图”；
     * **至少 1 处活细节**：微缩打字光标、呼吸状态绿点、或小幅数字跳动；
     * **构图带姿态**：轻度微倾斜（1°～2°）、局部越界溢出或堆叠感，打破死板贴框的模板感。
   - **优先级 3（纯排版大字报）**：采用巨字排版与极简留白节奏撑起张力，决不滥用无语义的装饰性色块。
   - **全页形状一致性锁（Border-Radius Lock）**：全页组件与卡片圆角必须统一度量（全直角、全 8~12px 柔和圆角或全胶囊），严禁不同模块大小圆角随意混用。
6. **痛点到解法（Problem to Solution）**：指出用户现状之痛，引出本产品的突破点（Before vs After）。
7. **核心利益点（Outcome-driven Benefits）**：3～5 个小节，遵循“利益先导（Benefit-first）”，说明“对用户意味着什么”。
8. **三步上手原理（How it works）**：用 3 个直观步骤展示使用流程，降低认知门槛与复杂感。
9. **深度社会证明（Social Proof）**：多维度真实客户评价、量化案例研究、实际产出展示。

### 第三幕：异议消除与收网转化（Bottom）
10. **常见异议解答（FAQ）**：6～10 题。FAQ 不是说明书，而是主动前置拆解不购买的借口。
11. **风险反转承诺（Risk Reversal）**：免费试用、无需信用卡、随时取消、无条件退款、安全合规认证。
12. **最终行动呼应（Final CTA）**：与首屏 CTA 保持完全一致的承诺与动作，作为最后一次转化机会。

## 4. 四类核心版式选型（Layout Archetypes）

新建或改版落地页做信息架构双选时，根据产品成熟度与用户意图选择最契合的版式模式：

| 版式模式 | 典型特征 | 适用场景 |
| :--- | :--- | :--- |
| **A. 经典产品截屏流 (Classic Hero + Sections)** | 左文右图或居中 Hero，下方大图直观展示产品核心工作区，中段平铺利益点与客户证明。 | 界面直观、用户一秒能看懂的 SaaS、工具类产品（最常见）。 |
| **B. 长文故事与深度说服流 (Long-form Story)** | 强化问题激化与逻辑推演，通过图文长流循序渐进地教育市场、拆解底层逻辑。 | 创新品类、高决策成本、需要克服严重怀疑的专业服务或复杂方案。 |
| **C. 极简极速转化流 (Minimal Conversion)** | 极短页面，首屏直接集成转化输入框（如邮箱），下方仅留 2～3 个核心信任背书与简短 FAQ。 | 来源意向极高（如邮件直推、老带新）、下载资源、预约报名、Waitlist 收集。 |
| **D. 对比与替代流 (Comparison Page)** | 突出竞品对比矩阵、痛点对比表与无痛迁移承诺，强调差异化优势。 | 针对“X vs Y”、“X 最佳替代品”等高商业价值搜索意向流量（SEO/AEO）。 |

## 5. 转化文案与心理学规范

### 1. 标题公式
- **结果与避痛**：`{Outcome} without {pain}`（如：“10 分钟完成报税，无需整理杂乱收据”）
- **品类与受众**：`The {category} for {audience}`（如：“专为独立开发者设计的极简支付网关”）
- **时效与交付**：`Ship {result} in {time}`（如：“3 天上线你的第一个自动化工作流”）

### 2. 文案纪律
- **利益先于功能（Benefit-first）**：功能是它做什么，利益是对用户意味着什么。先写加粗的利益结果，再紧跟具体机制（例：**极速迭代** —— 一键生成 3 套响应式布局变体）。
- **具体数值胜过抽象形容**：
  - 别写：“大幅节省您的工作时间，提升协作效率”
  - 改成：“把每周整理周报的时间从 4 小时压到 15 分钟”
- **动词先导 CTA**：不要“提交”“了解更多”“点击这里”，写清楚用户点了能拿到什么（“免费领取模板”“预约产品演示”“立即启动试用”）。
- **反虚假与反塑料味**：不要编 99.99%、50% 这类数字；社会证明和 Logo 必须真实可查，没有来源就留空或列进待确认。

### 3. 不要写 AI 腔

中文的 AI 味主要来自句式，不来自词够不够高级。下面这些骨架出现一次就要改写，改写方法见 `AGENTS.md` 的《说人话》：

| 别写 | 改成 |
| --- | --- |
| 不是 X，而是 Y / 不只是 X，更是 Y | 直接说 Y，需要对比就分两句 |
| 让 A 更高效、更透明、更可追溯 | 一句能核对的具体结果：每张单据都记经手人和时间 |
| 虽然还有局限，但值得期待 | 写清局限本身，或者删掉 |
| 一站式赋能、极致体验、助力增长、打造闭环 | 用户实际拿到什么，就写什么 |
| 值得注意的是 / 显而易见 / 众所周知 | 删掉，直接给事实 |
| 可能、或许、通常、一定程度上（叠用） | 只留一个最准的限定词 |

再加一条适用范围更小的：为排版对称凑出来的三连（三个形容词、三个同样的短句）通常只有一个是真的，留真的那个。

文案写完自查两件事：每句能不能被用户核对；把产品名换成别家是否还成立。仍然成立，说明这句还太通用。

## 6. 与系统现有规范的对齐底线

落地页在进入正式设计与切片实现时，必须无缝接入 `devstaff-1.0` 已有约束：

1. **唯一编排与状态流转**：
   - 落地页的结构决策依然写入 `.site/design/surface-brief.md`，走 `state.py discover` ➔ `select-structure` ➔ `decide`。
2. **视觉系统与 Token 继承**：
   - 颜色、字阶、间距、圆角必须绑定项目的语义 Token，严禁硬编码裸色值。
   - 遵循 `craft-review.md`：浅色/深色背景采用柔和的 off-black/off-white，拒绝刺眼的高饱和塑料发光色。
3. **图标与组件规范**：
   - 统一采用 **Lucide** 图标库，严禁私自引入互不兼容的图标体系。
   - 按钮动词先导，同视口仅允许单个 Filled 强调主操作；嵌套圆角满足同心公式（`outerRadius = innerRadius + padding`）；按压具备物理微缩放（`:active { transform: scale(0.96); }`）。
4. **轻量与性能底线**：
   - 拒绝华而不实的全局滚动劫持（Scroll Hijacking）或未节流的密集滚动监听。
   - 体验稿阶段严格保持轻量单文件快速预览，严禁堆砌重度测试。
5. **交付与无障碍保障**：
   - 包含完整的 SEO/AEO 基础（清晰的 `<title>`、Meta 描述、OpenGraph 社交卡片、语义化 HTML）。
   - 表单具备前端友好校验与防重复提交机制，输入框严禁拦截粘贴（Paste）。
   - 移动端窄屏必须保证主行动的可达性（避免被过长内容淹没）。
