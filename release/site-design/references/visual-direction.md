# 从项目事实推导视觉方向

本文件解决一个具体问题：**视觉方向从哪来。** 只规定“默认给一个推荐方向”不够——没有推导方法，结果仍会退化成通用页面套配色，或者去够“杂志感 / 海报感 / 粗野风”这类现成标签。两者都不是方向。

本文件给的是**推导与匹配方法**，不是固定配方，也不是"好设计长什么样"的规定。真正的好设计从这个项目的需求和内容里长出来；内置检索只在方向形成后帮助扩展和解释候选。

使用时机：新建、整体改版、信息结构变化，或延续现状但需要新的视觉表达时。局部色值、间距、文案和单个控件不做这一步。

## 0. 先确定"这是不是一次方向问题"

| 情形 | 是否需要本文件 |
| --- | --- |
| 新建页面、整体改版、主流程或信息结构变化 | 完整走五步 |
| 已有成熟设计系统，只新增一个页面 | 只做第 4 步的角色映射和第 3 步的例外说明 |
| 局部色值、间距、文案、单个控件 | 不做。用项目已有规则 |
| 只读审查 | 不做。核对该项目**已经声明过**的方向是否兑现 |

## 1. 五步推导

每一步都要能落成一句可核对的说明。写不出来就停在原地补事实，不要进入下一步。

### 第一步：内容事实——哪一个东西必须被看见

不是把内容全部列一遍，而是从项目事实里挑出**承担表达的那一个**：一个业务对象、一组数据、一个时间关系、一件实物、一段原文。

- 事实来自 `design-context.md` 的页面事实表和 `.site/brief.md`，不来自行业标签；
- 必须能回答"去掉它之后，这页还剩什么"。如果答不出，说明挑错了，或者这页本来不需要视觉主角；
- 真实内容优先：已有文案、真实数据形状、真实图片。没有就标缺口，不用示例内容代替事实。

### 第二步：视觉世界——它从哪来

视觉世界指这个东西在现实里属于什么材料、媒介和环境。**它是采样源，不是风格名。**

| 来源 | 例子 | 证据等级 |
| --- | --- | --- |
| 用户提供的真实素材、品牌资产、现有产品 | 用户给的实拍、截图、VI、色板 | `measured` |
| 参考站点、参考截图 | 用户指定的参考里可读到的排版比例、色彩、素材处理 | `measured` / `derived` |
| 业务对象的物理与行为属性 | 器物的材质、数据的量级与变化、流程的先后、场所的光线 | `derived` |
| 领域材料库 | 公共领域或许可清楚的素材（见 [工艺审查](craft-review.md)） | `derived` |
| 无法证实的解释 | 对受众偏好的猜测、对品牌气质的想象 | `inferred` |

`inferred` 可以用，但必须标注，且**不能单独支撑方向**：一个只建立在猜测上的视觉世界，等于凭通用直觉硬做。

### 第三步：设计主线——把视觉世界收敛成一个形式决定

设计主线是从视觉世界里提取的**一个可复用的形式决定**，用来贯穿整套页面：一种排版处理、一个尺度关系、一种材质或边缘语言、一个反复出现的结构关系。

设计主线必须可检验：

- **替换检查**：换一个客户名、换一个行业，它还成立吗？成立＝它不是设计主线，是通用装饰；
- **信息检查**：它是否真的帮某一类信息被看见？说不出来就是装饰；
- **成本检查**：外部字体或依赖加载失败、断网时它还成立吗？只有资源到位才成立的设计主线太脆：要么给它系统栈下的等价表达，要么换一个。

**没有设计主线时不进入配色和字体选择。** 用调色板或字体清单填空，得到的是没有立场的页面。

### 第四步：色彩与字体角色

颜色从品牌、真实素材、实际页面或业务材料采样并收敛成语义角色；字体按 display / 标题 / 正文 / UI / 数据分配职责。图标按按钮、导航与状态归入同一体系（默认 Lucide），不混用多套；Emoji 或 Unicode 字符只在有产品依据、识别一致且有可访问名称时作为例外。具体下限、中文排印、素材来源、许可与图标体系许可见 [工艺审查](craft-review.md)。检索到的色板或字体配对只是候选，不是采样来源或采用理由。

### 第五步：构图命题——一句话，能被证伪

用一句话说明这一页靠什么让用户先看到该看到的东西。例如"主轴是一条时间线，最新在上"、"首屏只有一个数字，其余全是注解"、"左栏是对象，右栏是它的历史"。

- 必须指名**主次关系**和**它靠什么成立**（尺度、位置、对比、留白、运动中的一种或几种）；
- 必须能证伪：如果删掉这个手段，用户先看到的东西变了，命题才成立；
- 构图手段、栅格、留白与细节签名按 [工艺审查](craft-review.md) 核对。

## 2. 从需求匹配风格候选

用户需要比较风格时，在完成五步推导后把上下文收敛成一份匹配画像：

```text
表达强度：大胆 / 中性 / 安静，由受众、风险与品牌边界决定
内容主角：文字 / 数据 / 实物或人物 / 操作界面 / 时间与空间关系
信任姿态：权威 / 人文 / 实用 / 实验 / 技术精确
领域后果：已确认的信任、隐私、可逆性、时效、监管或专业性要求
信息密度：紧凑 / 舒适 / 舒展，由任务频率和内容量决定
素材条件：已有摄影、插画、品牌资产、数据，或明确缺口
交互强度：静态阅读 / 状态反馈 / 连续操作 / 沉浸叙事
基调旋钮：VARIANCE (1~10) / MOTION (1~10) / DENSITY (1~10)（如 Tooling 基准 2/2/8，Marketing 基准 7/6/3）
```

用画像筛选，不做随机抽签或固定的“稳妥 + 大胆 + 折中”组合。需要扩大候选池时，按 [工具链](design-toolchain.md) 查询 `style` 或 `--design-system`；记录实际查询后仍用本节规则筛选，不能把排名、预设或工具推荐当成项目证据。风格结果要翻译成可见机制，例如排版主导、编辑式网格、工具化高密度、材料触感、沉浸式叙事、结构主义边框或克制极简；名称只是沟通标签，真正被采用的是布局、组件、密度、重心和材质机制。

一个候选成立需要同时满足：

- 至少两条上下文证据支持，其中有现成设计或真实素材时至少一条为 `measured`；
- 行业名称本身不算证据；只有已被项目事实确认的领域后果才可作为 `derived` 依据；
- 不与已确认范围、设计系统、内容量、素材现实、无障碍或设备条件冲突；
- 风格家族经过项目化翻译，产生自己的设计主线与构图命题，不直接复刻参考品牌的颜色、字体、组件或标志性画面；
- 依赖的摄影、插画、动效或高级实现真实可得；拿不到时降级会不会失去方向，必须在展示前说明。

风格名可以出现在给创作者的说明和 [页面设计合同](surface-brief.md) 的视觉方向表里，帮助理解和选择；它是结果的短标题，不是证据，所以不上预览页的切换条（标签固定写 `方案 A` / `方案 B`），也不当顶栏说明句开头的标签，规则见 [体验稿](prototype.md) 的视觉体验稿铁律。每个候选都要用日常语言说明：**为什么适合这个项目、它会让什么更突出、会牺牲什么。**

## 3. 视觉风格双选与轻量对比

骨架被用户选定之后（`state.py select-structure` 记下他的原话之后），先按 [体验稿](prototype.md) 问一轮参照物：用户给得出（自家产品或品牌素材、别人的网站、一张截图）就按 [参考输入](reference-input.md) 做一版贴着参考的，不凑第二版；给不出，新建与重大改版**默认提供 2 种视觉风格差异显著的方案**供用户直观选择。骨架还没选定就不做这一步：选视觉之前必须先有选定的骨架。两版候选必须**在设计主线层与视觉世界不同**，不是在同一页面上换调色板。

**候选差异判据（7 轴发散与遮色自检）**：
候选差异必须发生在设计轴上，不能仅停留在表面涂色。建立 7 大正交轴自检：
1. **明度轴**：亮底 ↔ 暗底；
2. **字体家族轴**：无衬线现代 ↔ 衬线人文 ↔ 等宽工业 ↔ 艺术展示体；
3. **色彩策略轴**：单色克制 ↔ 双色对撞 ↔ 多色系统；
4. **布局结构轴**：对称网格 ↔ 编辑杂志不等比 ↔ 自由流体构成；
5. **密度轴**：美术馆宽阔留白 ↔ 紧凑控制台；
6. **时代气质轴**：复古印刷 ↔ 当代科技极简 ↔ 未来科幻；
7. **材质质感轴**：极平扁平 ↔ 物理纸质印刷 ↔ 微拟物触感。

- **硬性判据**：双选的两套方案**至少在 3～4 条轴上取值截然不同**，且必须包含“明度轴”或“时代气质轴”之一；
- **遮住颜色自检（Color-blind Test）**：将两个候选全部抽掉颜色变为纯灰度，如果骨架留白、空间韵律与排版层级依然清晰可辨，才算两个独立方向；互换两个候选的配色和字体后差异基本消失的，判定为换肤反模式，直接判为不合格。

### 轻量对比与防过度测试（铁律）

视觉双选的目标是让用户直观看到视觉方案并定调，绝不能沉重：
- **极简呈现**：只做单页轻量预览，仅呈现首屏与最具代表性的核心卡片；
- **拒绝业务逻辑**：数据全部写死，不写业务逻辑代码，不连真实数据库或假接口；
- **严禁过度测试**：**绝对禁止在此阶段执行单元测试、合同校验（`check-contract` 留给 prebuild）或自动化跨端深度测试**，仅做基础的 HTML 语法可渲染检查；
- **不承诺绝对速度**：使用“轻量快速生成”等客观表述，不承诺“秒级”。

### 换肤反模式（直接失败）

以下实现只能算一个方向，不能作为两个候选交付：

- 同一套 HTML 骨架、同一组组件顺序和同一套 CSS 布局，只通过 `data-theme`、CSS 变量、颜色、阴影或字体切换来制造差异；
- 两个候选在黑白化、统一字体、关闭阴影后仍然拥有相同的栅格、卡片形态、信息密度和视觉重心；
- 只更换风格名、色板或图标，不更换承载主任务的组件形态或构图关系。

实时切换体验稿可以共享数据和交互状态，但必须由两套明确的 DOM/渲染分支承载；只切换主题属性不合格。

同时满足：

- 固定已选定的骨架结构、同一组真实内容、状态和主要操作；视觉方案不改变信息架构；
- 每个候选写出自己的匹配依据、第 1～5 步结论，尤其是**设计主线**和**构图命题**；
- 候选使用项目可获得的同一批素材，不靠不同素材质量制造差异；
- 每个候选只做到足以判断，不展开全部页面；
- 给出一个推荐项及理由，同时允许创作者选择、混合或快速微调；推荐不等于替用户确认；
- **资产平滑继承**：用户确认满意的 Demo 直接作为正式代码胚胎，CSS 变量沉淀为正式 Token，核心 HTML 结构直接作为第一条纵向切片模板。

检索词和风格家族可以帮助命名和扩展候选，但以下内容不能单独产生候选：

- 只有风格标签（海报感、杂志感、科技感、粗野风、极简），没有项目匹配依据；
- 相册或配方目录里的相邻选项；
- 同一个设计主线的三种强度；
- 为制造反差而随机加入的大胆款。

## 4. 反默认

形成方向前，先写出**这个类别最容易出现的生成式答案**，再写清本项目事实为什么不采用它、用什么替代。

这条是判断方向是否真正形成的门槛：写不出"类别默认是什么、我为什么不照做"，说明方向还没形成，不要进入 token 选择。采用类别标准不是失败，无法说明它为何适合当前事实才是惯性；最终用 [工艺审查](craft-review.md) 的四个设计判断核对。

## 5. 边界与诚实

- **风格匹配不是风格抽签。** 检索只提供可调用的视觉机制；候选仍要由项目证据筛选、翻译并接受冲突检查；
- **设计主线推不出来时，如实说方向未形成**，不要用配色、字体或装饰填空，也不要用"高级感""电影感"这类无法证伪的词；
- **配方目录（`tokens.json`）只做实现校准**：它把已经形成的方向转成一致变量，不产生设计主线、不产生信息架构，也不是"随便选一个都成立"的保证。方向未被确认时，选配方不构成方向；
- **方向与结构是两个设计轴，但只形成一个完整决定。** 视觉表达以当前结构为基础；结构发生实质变化时，旧视觉方向需要重新核对，再确认整个方向；
- 素材来源、许可和裁剪必须记录并在展示时说明；无法获取时用诚实缺图，不冒充真实素材。

## 6. 交接

把推导结果写进 [页面设计合同](surface-brief.md) 的“视觉方向”一节，随稿件一起交给 `site-brief` 记录：

```text
内容事实：哪一个东西承担表达
上下文依据：路径、页面或素材 + 精确观察 + 证据等级
匹配画像：表达强度、内容主角、信任姿态、领域后果、密度、素材和交互
视觉世界：来源、证据等级、已知缺口
设计主线：形式决定 + 替换检查结论
色彩来源：采样自什么、收敛成哪些语义角色
字体角色：display / 标题 / 正文 / UI / 数据各用什么、为什么
图标体系：常规 UI 图标体系名；Emoji/Unicode 例外及其产品依据与可访问名称
构图命题：主次关系 + 它靠什么成立
细节签名：哪一处做到 120%，它服务什么内容
素材：来源、许可、裁剪与用途
候选：风格短标题 + 匹配依据 + 突出什么 + 牺牲什么
推荐：推荐项及理由；等待创作者选择
```

方向与结构是两个设计轴，采用“骨架双选 ➔ 视觉（先问参照物：贴参考一版，或双选两版）（轻量且可继承）”的递进确认，并在视觉风格选定与微调满意后，由 `site-builder` 记录一次 `decide` 锁定完整方向进入构建；本文件不写协作状态，也不授予高风险操作。
