# 构图、尺度与节奏

构图决定用户先看到什么。它由视觉重量、尺度对比、对齐、留白和密度共同构成，每一项都有可观察的判断标准——"感觉平衡"不是标准。

使用时机：方向合同与母题确定之后，进入实际页面之前和之中。

## 1. 视觉重量与任务一致

页面最先被看到的东西，必须是用户此刻最需要的东西。

判断方法：**眯眼测试。** 眯起眼看页面（或看缩小到 25% 的截图），剩下的那团重量在哪里？它是否就是这个页面的主任务？

- 主任务获得最大视觉重量，主行动是页面上最容易找到的可操作元素；
- 同一操作区域内的主次按钮有清楚区分，不是两个同样显眼的按钮并列；
- 当"最先看到的东西"与主任务不一致时，改构图，不要靠加文字说明补救。

## 2. 尺度对比

元素之间的差异必须**可感知**，不能"都还行"。

- 主要元素与次要元素之间至少有一处明显的倍数差（尺度、字重或面积）；
- 全部元素大小接近时，页面读起来是平铺的，用户找不到入口；
- 尺度对比要服务信息重要性，不是为了制造戏剧性：把不重要的东西放大同样是错；
- 一页里承担"最大尺度"的元素只应有一个。两个都想当主角，等于没有主角。

## 3. 栅格与对齐

- 选一套栅格（列数与间距）并让它贯穿页面。临时插入的宽度会立刻显形；
- **边缘对齐是底线**：同一组内容的左右边界、控件高度、图标基线要对齐；
- 基线对齐比顶部对齐更重要：一行里混排的文字、徽标、按钮要有共同的视觉基线；
- 不对齐必须是决定（有理由、可说明），不能是疏忽。审查时把"这里为什么不对齐"当问题问；
- 容器嵌套会带来边框噪音：需要独立操作、选择或状态的区域才用容器，其余靠留白、排版和分隔线表达关系。

## 4. 留白

**留白是构图，不是内容缺席。** 靠减少内容腾出的空间不是设计，是空白。

留白成立的条件：

- 首屏有明确的视觉锚点，视线有落点；
- 留白有方向性：它把视线推向主要内容，而不是均匀散开；
- 留白量随内容重要性变化，不是全页一个节奏；
- 缩小到 25% 看时，页面仍有结构，不是"几个小字漂在大片空白里"。

**安静派的失败模式**：大片留白配微缩字号，第一眼像页面渲染坏了。留白越多，剩下的元素越要经得起看——尺度、字重、颜色都必须明确。安静不等于弱。

## 5. 密度

密度由**任务**决定，不由行业决定：

- 高频比较与批量处理：紧凑，信息可并列，减少一次滚动内的判断成本；
- 普通使用：舒适，一屏能看完整组内容；
- 展示与阅读：舒展，让内容本身成为主角。

限制：

- 紧凑模式不能靠压小正文实现。字号下限、行高下限和可点击尺寸在任何密度下都成立；
- 密度不同的两个区域可以在同一页共存（例如紧凑的列表 + 舒展的详情），但栅格与对齐必须一致；
- 密度低不等于把内容摊开——少内容时重新构图（单条内容怎么排、两条怎么排），不是把同一布局拉宽。

## 6. 极端内容

真实数据不会刚好是"三项、每项两行"。以下情形必须各自设计，**不能用假数据填满**：

| 情形 | 要求 |
| --- | --- |
| 空 | 说明为什么空、下一步能做什么。不伪造占位数据 |
| 一项 | 单个内容的构图与列表构图不同，不要留下大片空白 |
| 很多项 | 分页、滚动或分组有明确策略，计数与范围与内容一致 |
| 超长文本 | 截断策略明确，能看到全文的路径存在 |
| 缺图 | 有设计的缺失状态；不用色块冒充真实图片 |
| 长数字与大额金额 | 不换行、不错位，列宽按最坏情况定 |

## 7. 细节签名

**一处做到 120%，其余做到 80%。** 这是把"反 AI 味"从否定清单变成正向目标的关键：与其全页均匀用力，不如选一处真正服务内容的细节，做到值得截图。

合格的签名必须：

- **服务内容**：它是那条数据、那件实物、那段原文的表达方式，不是装饰；
- **可复用**：在同类位置重复出现，形成规则，而不是孤立的特效；
- **不牺牲可用性**：不挡住主任务，不拖慢加载，不破坏对比度和对齐；
- 能被一句话说明白"这里为什么这样做"。说不出来就是装饰。

反面例子：全页渐变、每个标题配图标、每块内容包进圆角卡片、无依据的发光——这些是均匀用力的装饰，不是签名。

## 8. 动效

- 动效**解释状态变化**（展开、切换、反馈、位置关系），不是给页面加活力；
- 不拖延主要操作：用户点完要立刻看到结果，动画可以在结果之后；
- 一次编排好的进入节奏，优于散落各处的微交互；
- 尊重 `prefers-reduced-motion`；
- 静态页面也可以精致。没有动效不是缺陷，为了"活起来"而动才是。

## 9. 强度分级

- **硬下限**：主任务可达且视觉重量对应、边缘与基线对齐、字号与行高下限、可点击尺寸、极端内容不靠假数据、减少动态效果；
- **条件性风险**：需要加载大量媒体或复杂交互的签名效果（影响性能或首屏时需重新取舍）；
- **可覆盖启发式**：栅格列数、留白量、密度档位、签名位置。项目事实、成熟规范或有依据参考可以覆盖，必须说明依据。

## 10. 常见错误

| 表现 | 为什么是问题 | 改法 |
| --- | --- | --- |
| 巨大欢迎标题 + 统计卡 + 等宽卡片网格 | 各类工具都套同一结构，主任务被挤到后面 | 用实际任务决定首页，先展示待处理内容或主编辑区 |
| 所有内容包进圆角卡片 | 层级被相同容器压平，边框成为噪音 | 用列表、段落和对齐表达关系，只保留有独立含义的卡片 |
| 留白很大但元素很小很弱 | 像渲染坏了，安静派最常见的失败 | 提高剩余元素的尺度与对比，或减少留白 |
| 一页多个同等显眼的元素 | 没有主角，用户不知道先看哪里 | 定一个主尺度元素，其余降级 |
| 密度靠压字号实现 | 可读性受损，触控目标过小 | 改布局（换列、分组、折叠），不改字号 |
| 空状态用假数据填满 | 掩盖真实的方案缺口 | 设计诚实空状态并说明缺口 |

构图判断有一个统一的落点：**把页面缩小到 25% 看，它是否仍然清楚、有重心、像一件成品。** 如果这时它变成一团模糊的灰，问题在构图，不在细节。
