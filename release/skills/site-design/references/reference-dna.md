# 参考还原：量出来的那一部分

用户说“参考这个网站”“做成类似那样的”时，他要的不是那家网站的内容，是**把他自己的内容装进那个网站的设计语言里**。这件事是哪一种（还原 / 借鉴 / 功能相似）、用哪一张参考、素材怎么数，见 [截图或网址输入](reference-input.md)。这一份只管两件事：**怎么把看到的东西变成可核对的值**，以及**怎么知道实现跑没跑偏**。

## 先看手上是哪一路

图片和网址能取到的证据差一个量级，不要按同一套走：

| 手上是什么 | 主证据 | 旁证与验收基准 | 写进合同的值以谁为准 |
| --- | --- | --- | --- |
| 网址，打得开 | 浏览器里读 computed style 与 CSS 变量 | 同视口截图 + `measure` | CSS 的 |
| 只有图片文件 | `measure` 的像素测量 | 无 | 测量的，并知道它的精度边界 |

| 失败 | 防线 | 代价 |
| --- | --- | --- |
| 量不准：凭“看”报色值，向常见调色板默认值漂移 | `dna.py measure` / `dna.py recon` | 一条命令 |
| 漏项：只抄了颜色和排版，漏掉参考站最显眼的动效 | 三维查漏清单 | 一轮比对 |
| 误以为像：实现和参考差多少，没人知道 | `dna.py verify` | 一条命令 |

## 有网址：先读 CSS，再截图

网址这一路**不要**从截图上量色。截图里根本没有字体名、没有字号绝对值、没有动效时长；而 CSS 里这些都是浏览器算完的精确值。

```text
# 1) 在真实浏览器里跑侦察（宿主浏览器工具不同，传参不同，这一份就是普通 JS）
playwright-cli eval "$(cat dna/scripts/recon.js)" > /tmp/recon.raw

# 2) 收成项目证据格式，先看摘要（完整结果落盘，摘要只印有上限的视图）
python3 dna/scripts/dna.py recon /tmp/recon.raw \
  --out .site/design/reference/recon.json --summary

# 3) 同视口截图，作为验收基准，落到 .site/design/reference/
playwright-cli resize 1440 900
playwright-cli screenshot
```

摘要里有三样立刻要用的东西：

- `candidates`：`canvas / text / muted / accent` 的候选值，**每个都带来源和排序理由**。只给候选不给结论——一个站可能有两个同饱和度的品牌色，选哪个是内容决定的，不是脚本能决定的。合同里的最终值看一眼再写，并记下你选了哪个。
- `typeScale / lineHeights / maxWidths / radii / shadows / motion`：从整页频次里读出来的刻度。单个元素给不出规律，频次能。
- `effects`：第三维的取证（下面查漏清单要用）。

`accent` 的候选要留神：高饱和的颜色常常是语法高亮配色或调色板色阶，不是品牌色。脚本按变量名打折（`--sk-*`、`--gray-*`、`--*-500` 这类），拿不准时 `candidateNotes` 会提示你按名字再找一遍 `brand / primary / accent / link / focus / ring`。品牌色还可能只存在于形状里——bun.sh 的品牌粉就藏在 `--ring` 的两层焦点环中间，脚本会把这种内嵌值挖出来并标上「内嵌在形状里」。

### CSS 给得出、像素给不出的

| | 图片 | 网址 |
| --- | --- | --- |
| 精确色值 | 量得出（文字那一档有偏差，见下） | 精确值 |
| 字体名 | **不能**，只能判类别 | `font-family` 实际值 |
| 字号 / 行高 / 字距绝对值 | **不能**，只能判相对关系 | px 绝对值 |
| 圆角 / 阴影 / 间距刻度 | 只有相对观感 | 实际值 |
| 动效时长与曲线 | **不能** | computed transition / animation |
| 技术栈 | **不能**，只能推断 | 脚本依赖 + canvas / WebGL 上下文 |
| 布局与响应式重组 | 只有单帧 | 换视口重跑 `recon.js` |
| 交互与滚动行为 | **不能** | 实际操作 |

同一个站两条路都走一遍，差别是这样的（bun.sh，1440×900）：

```text
CSS：文字 rgb(10, 10, 10) = #0a0a0a   品牌粉 rgb(255 31 143) = #ff1f8f
     标题 Archivo 68px / 62.56px / -1.36px / 800
像素：文字 #0c0c0c（被背景拉过去了）   品牌粉 #ff208f（ΔE 0.4，对上了）
     另 4 个聚类是抗锯齿混合，加起来占 3.3% 面积
```

所以有个反直觉的结论：**品牌色两条路量出来几乎一样，文字色只有 CSS 说得准。** 这就是为什么有网址时不从截图上量色。

### 侦察看不到什么

`notObserved` 会列出来，别把缺失当成没有：跨域样式表里的规则读不到（`stylesheets.inaccessible` 会给出份数）、其它视口下的重组要重跑、登录后的页面与交互结果要实际操作。

两个数专门用来把“没加载完”和“这个站就这么简单”分开：`page.readyState` 不是 `complete`、或者 `elementCount` 小得不正常时，`notes` 会提醒你重跑。跑太早的页面看起来和空壳页一样，而 `roles` 很可能已经有几个了，不会自动判失败。

## 只有图片：量

模型对颜色的感知会向熟悉的值漂移。上游实测：品牌粉 `#ff90e8` 会被看成 `#ec4899`，ΔE ≈ 29 —— 肉眼看还是同一类粉，写进合同后就是另一个品牌。更麻烦的是**估出来的值和量出来的值长得一模一样**：都是六位十六进制，读合同的人分不出哪个是猜的。所以参考只有图片文件时，色值一律以测量为准。

```text
python3 dna/scripts/dna.py measure <参考截图> --k 6 --out .site/design/reference/measured.json
```

- `palette[].hex`：精确色值，**逐字抄进合同**，不四舍五入、不换成“接近”的值。
- `palette[].coverage`：这个颜色在画面里占的比重（0~1）。覆盖率 0.0001 的“强调色”不是强调色，是抗锯齿残渣。
- `palette[].role`：`background / text / accent`，按覆盖率、明度对比与饱和度判出来的候选归类；不合内容语义时以你看到的事实为准。
- `measurement.k` 与 `measurement.decoder` 一起抄进合同：验证要用同一套聚类配置重跑，换了 k 比的是参数差异，不是设计差异。

`k` 取 **4~6** 比默认的 8 实用：真实页面上多数聚类是抗锯齿混合（上面 bun.sh 那 8 个里有 4 个），k 大了只是让混合值占掉聚类名额。

截图和 `measured.json` 都放 `.site/design/reference/`，别留在临时目录：验收证据要能被别人重跑。多个视口各一份，按 `measured-<宽>x<高>.json` 命名。

## 量得出来的和量不出来的

一屏截图能确证的东西比合同要求填的少得多。**不要为了把字段填满而编值**：

| 合同字段 | 从图片 | 从网址 |
| --- | --- | --- |
| 颜色 `canvas` | `background` 的 hex | `html` / `body` 的 `backgroundColor`（两者不一致时背景挂在 `html` 上） |
| 颜色 `text` | **只能得到近似值**：聚类中心包含笔画边缘的抗锯齿，会被背景拉过去（实测真值 `#0a0a0a` 量出 `#0c0c0c`）。写进合同标 `measured`，但别声称它是精确的品牌值 | 精确值 |
| 颜色 `accent` | 有覆盖率支撑的 `accent`；没有就是没有 | `candidates.accent` 的候选，选一个并说明依据 |
| 颜色 `surface` / `border` / `border-control` / `focus` / `success` / `warning` / `error` / `on-accent`… | **一屏里通常看不到**。按 `derived`（由可见的相邻色对推导）或 `inferred`（判断）填并写明依据 | 同样多半看不到；能从 CSS 变量里找到就标 `measured` 并记变量名 |
| 字族 | 只能判类别（几何无衬线 / 人文无衬线 / 衬线）与字重字距的观感。**不声称具体字体名** | 实际字体栈 |
| 字号与尺度比 | 多张同视口截图之间可以比出相对关系；绝对值不超过 `derived` | 绝对值 + 整页频次 |
| 间距、栅格、圆角、阴影、图标笔画 | 观察得来的相对结论，标 `derived` | 实际值 + 频次 |
| 动效时长与曲线 | 静态截图看不到，标 `not-visible` | computed 值；实际手感仍要滚一遍才算 |

上游 schema 要求“每个字段都必须有值、宁可推断也不留空”。这一条本项目不采用：一个只有截图的项目，要把 `warning` 色填满就只能猜，而猜出来的值进了合同就变成要验收的标准。**填不满就留空并写清缺什么**，比填一个没人能核对的值有用。

## 三维查漏清单

只抄颜色和排版是“参考”里最常见的漏项：参考站的辨识度常常全在动效和材质上，而那部分在静态截图里最容易被跳过。三个维度逐项过一遍，每项标证据强度：

1. **设计系统**（可量 + 可观）：颜色、字族角色、字号尺度、间距密度、栅格与最大宽度、圆角、边框与分割线、阴影层次、图标体系与笔画、动效。
2. **定性气质**（只能推）：情绪、视觉隐喻、年代影响、品类原型、繁简程度、留白策略、视觉重心、对比强度、构图手法、图像风格、交互气质。
3. **视觉特效**（从行为和源码看）：Canvas、WebGL / 3D、粒子、着色器、滚动驱动动效、光标特效、文字特效、玻璃拟态、SVG 动画。

第三维怎么取证：

- **有网址**：`recon.json` 的 `effects` 已经给了 canvas 数量与上下文、脚本依赖、命中的全局对象（`THREE` / `gsap` 这类）、渐变与 `backdrop-filter` 数量、视频与内联 SVG 动画。再去实际操作一遍滚动和悬停——`recon` 给的是静态事实，编排要动过才知道。
- **只有静态截图**：只写**看到什么**（“右上角有一片持续漂移的半透明光斑”），不写**用了什么**。“这是 WebGL”是推断不是观察，标 `inferred`。
- 定下要做之后，实现注意项查内置工具链，不凭记忆写：

```text
python3 scripts/design.py research --query "..." --stack threejs
```

（内置 22 个栈、1260 条准则；Three.js 的版本钉法、几何体、控制器的正确写法都在里面。）

**参考站没有的东西也要记。** 确认它没有粒子、没有滚动特效，能防止实现里顺手加一堆没有来源的动效。

## 闭环：自己改到通过，不要让用户判“像不像”

实现出来之后，用同一个视口、同一档内容截一张实现截图，和参考基准比：

```text
python3 dna/scripts/dna.py verify <实现截图> .site/design/reference/measured.json \
  --out .site/design/reference/verify.json --summary
```

| 指标 | 阈值 | 它拦的是什么 |
| --- | --- | --- |
| 平均 ΔE（按实现面积加权） | ≤ 5 | 整体色调偏了 |
| 最大 ΔE（显著覆盖率内） | ≤ 20 | 某个颜色被换成了另一个 |
| 覆盖率偏差合计 | ≤ 0.35 | 某个颜色整个漏掉或被用得过多 |

退出码 0 通过、2 不通过。**不通过就自己改色再重跑**，别拿“看着差不多”去问用户——那等于把我们该核的事推给他。改了色重跑，直到通过；或者直到你确认差距来自内容本身（参考是深色产品站，用户的内容是一页白底文档，色板本来就不该一致）。这时**如实说明差在哪**，不要改阈值来让它过。

比对的边界：

- 两张图要同视口、同档内容、同主题。拿手机截图比桌面参考、或者拿空状态比有数据的参考，算出来的 ΔE 说明不了设计差异，如实记 `not-visible` 或说明范围，别把它当通过。
- `verify` 需要一份 `measured.json`。有网址时要先量一张参考截图（`measure`）才能用它当基准——`recon.json` 和它是两份东西，各自记录不同的证据，不能互相替代。
- 这个闭环只在**视觉方向定下来之后**用。它不是方向本身：色板只用来校准已经成形的位置，不能拿一组量出来的颜色代替设计判断。
- **数值不进检查报告。** 报告里写 `observed`（看到什么）和 `evidence`（文件在哪）；数字由任何人在任何时候重跑 `verify` 得到。往报告里填一个数，读者无法核对，却长得像测量结果——比不写更糟。

## 不要做

- 不因为 `measure` 给了三个角色，就以为合同的十二个颜色角色都有着落。
- 有网址却去截图上量色，把文字色量成混合值再写进合同。
- 不把量出来的色板当设计方向；它校准颜色，不产生主线、不产生结构。
- 不照搬参考站的 Logo、品牌色、专有字体和标志性画面。别人的站只借布局、密度、层级和调性。
- 不声称截图能证明的东西：登录、支付、隐藏页面、服务端行为、技术栈。
- 不改阈值让结果通过。

## 出处

`dna/scripts/dna.py` 的 `measure` 与 `verify` 是 [zanwei/design-dna](https://github.com/zanwei/design-dna)（MIT）的 `scripts/measure-colors.mjs` 与 `scripts/verify.mjs` 的 Python 移植：算法、合并阈值、角色判定与 PASS/FAIL 标准都保持一致。差别只在运行时——本项目只用 Python 标准库，PNG 自带解码，不引入 Node 与 `sharp`，否则平台包就不再是“解包即可复现”的快照。

`dna/scripts/recon.js` 与 `dna.py recon` 不是移植，是本项目自己加的：上游没有网址这一路，它的做法是一律截图再量。许可与移植记录见 `dna/LICENSE` 与 `dna/VERSION`；跨实现一致性由 `dna/scripts/tests/test_dna.py` 里钉住的上游输出保证。
