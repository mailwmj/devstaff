# 动效：定一张能指认的节拍表

对外营销站、品牌官网、活动页和产品发布页需要这一节。工作台、办事指南、数据看板不需要——那里按 [工艺审查](craft-review.md) §5 的高频零动效执行。

本文件解决一件事：页面上哪里动、动成什么样、用户能不能一眼看出。它给的是正面手法和预算，不是效果目录；运行前提是本包的硬边界——**不引第三方动效库**，离线、弱网和低端设备都要打得开。

## 1. 帮用户选，不问他想要什么

「炫酷」「高级」「加点动效」这类词选不出任何东西。问用户“你想要什么效果”，只会拿回同义反复（“就是要好看那种”）或者一个别人的网站。**不要问，也不要把动效做成一轮二选一**：跟着方向一起给一次，用户只需要点头或否决。

给法：一行一拍，写他看到什么，不写技术名。

```text
首屏    标题从下往上落位，背景照片缓慢推近一点
滚动    第二段开始时左边画面固定住，右边文字一屏一屏替换
交互    鼠标移到案例卡上，卡片轻轻抬起，阴影变深
收尾    底部联系方式淡入一次
静止版  关掉动效时：标题就位、照片是原图、文字全部可见
```

后面附两句最可能做反的，让他一个词就能回答：

```text
不对的话最可能是这两点：① 不想要会动的背景，静态照片即可 ② 首屏不要推近，直接铺满
```

要求：

- 每一行都是**看得见的东西**（位置、快慢、先后、变深变浅），不是“沉浸式”“电影感”“高级动效”这类形容词；
- 不出现技术名（Canvas、GSAP、视差、FLIP、View Transitions）：用户读不出区别，也就无法否决；
- 两个否决点必须是两种不同做法（主题、静态/动态），不能是一个问题的两种说法；
- 用户不回话就按这张表做；他指哪条改哪条，不重新问一轮，也不在 `site-brief` 里加动效问题。

## 2. 四拍，一页不超过四拍

| 拍 | 位置 | 负责什么 | 上限 |
| --- | --- | --- | --- |
| 首屏 | 第一屏 | 让第一眼有明确的视觉主角 | 1 拍，全页重拍最多 1 个 |
| 滚动 | 中段 | 把长内容切成有节奏的段落 | 2 拍 |
| 交互 | 全页 | 让可点的东西有回应 | 1 拍，同一套反馈复用 |
| 收尾 | 页尾 | 把行动入口再强调一次 | 1 拍 |

- 同一手法不重复两次；四拍里最多一个“重拍”（持续动画、滚动叙事或大画布）。
- 首屏那一拍不能挡住主行动：标题和按钮不依赖动效就位（见 §4）。
- 首屏初始渲染不做入场动效（[工艺审查](craft-review.md) §5）：第一屏的拍子从滚动或交互开始，避免加载闪烁。
- 内容不足一屏半的页面只留交互拍，不为了“有动效”硬加。

## 3. 零依赖手法表

表内全部使用浏览器自带能力，没有第三方库。**每一行的前提是不支持时降级到静止，信息不丢。**

| 手法 | 用户看到什么 | 服务哪类内容 | 廉价版（别做成这样） | 依赖与兜底 |
| --- | --- | --- | --- | --- |
| 滚动揭示 | 内容进入视野时就位一次 | 分段说明、卖点 | 每段都从透明淡入，整页一个节奏 | IntersectionObserver（几行脚本）或 `animation-timeline: view()`；不支持时直接显示 |
| 固定 + 换屏 | 画面固定住，文字逐屏替换 | 一条流程、时间线、做法步骤 | 钉住的内容和文字无关，纯摆拍 | 纯 CSS `position: sticky` |
| 画面显影 | 图片从模糊或暗处显出来 | 氛围图、实物、案例 | 全页图片套同一种滤镜，像模板 | CSS mask / clip-path / filter；静止时是原图 |
| 数字就位 | 关键数字从 0 走到目标值 | 成果、规模、统计 | 数字没有来源，或精确到小数点后两位 | `@property` + counter 或几行脚本；静止时直接给终值 |
| 标题落位 | 标题逐字或逐行落位 | 品牌语气、活动主题 | 整段正文逐字出现，读起来被拖住 | 纯 CSS，只用于标题 |
| 错位入场 | 卡片以不等距的节奏出现 | 作品、案例、商品 | 所有卡片同一延迟，像加载动画 | CSS transform / opacity |
| 光标回应 | 按钮被光标吸一下，卡片带一点视差 | 桌面端交互质感 | 触摸设备上也在跑，手指点不准 | 只对 `hover: hover and pointer: fine` 生效 |
| 页面转场 | 切页时内容从右侧推进 | 多页站点 | 每个链接都转场，返回时闪白 | View Transitions；不支持时硬切 |

参考站用 Three.js / WebGL / GSAP 做出来的效果，按 [参考还原](reference-dna.md) 的第三维记录“看到什么、推断用了什么”，实现仍走本表。**不引依赖不是保守，是这个包的验收线**：断网、弱网和低端设备上，外部库先坏，页面内容不能跟着坏。

## 4. 四条硬约束

1. **静止帧是设计的一部分。** `prefers-reduced-motion` 下不是“关掉动画”，是定格在构图最好的一帧：图是原图、数字是终值、文字全部可见。
2. **起始态不能是“看不见”。** 以 `opacity: 0`、`translateY(...)`、`clip-path` 收起为起始、等触发器才出现的元素，在减少动态或脚本失败时是**永久不可见**的。写成“最终态是作者态，从别处动进来”。
3. **渐进增强。** 动效全部去掉后，信息和操作必须完整；正文和行动按钮不依赖动效出现；动效不承担唯一信息（“滚到才看得到价格”不成立）。
4. **只动 `transform` / `opacity`，不阻塞首屏，不写 `transition: all`。** 支持面还在铺开的能力（`animation-timeline`、View Transitions）当增强不当基础。

## 5. 什么时候不动

- 工作台、数据看板、办事指南、表单：0 拍，按 [工艺审查](craft-review.md) §5 的高频零动效执行；
- 页面上没有值得动的内容：不动，不硬加；
- 用户明确不要动效：全部去掉后仍必须完整，这是一次真实可用的降级，不是残缺版。

## 6. 交出去之前

- 每一拍都能说清“服务哪条内容”吗？说不出就删。
- 超过四拍、首屏超过一拍、有同族重复吗？
- 减少动态后的那一帧，是一张能拿出去看的构图吗？
- 有没有以“看不见”为起始、靠触发器才出现的元素？
- 把动效全部去掉，页面还成立吗？
- 节拍表里有没有用户看不懂的技术名？

给关键的一拍写一条 `VA-*`（例如“开启减少动态后，首屏标题与按钮完整可见”），它会由 `site-check` 在浏览器的视觉轴上复核。
