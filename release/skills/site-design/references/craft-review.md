# 工艺审查与只读评审

本文件是视觉质量、排版、色彩/素材、构图、任务界面和评审证据的唯一运行时协议。只读评审与体验稿自检使用同一把尺；区别是只读评审不修复、不写项目、不改变确认状态。

## 1. 固定评审帧

先固定 `页面 / 状态 / 内容 / 视口 / 主题`。候选比较和修复复验必须保持这些条件一致；条件不同就不能声称前后或方案间优劣。

最小证据集：

- 代表页面与主路径、一个重要异常或空状态；
- 适用的宽屏和窄屏，必要时加内容开始失效的中间宽度；
- 一份能回到页面/状态/视口的截图或操作记录；
- 每项结论标 `passed | failed | not_run | not_applicable`，无证据就是 `not_run`。

只读任务允许的操作只有：读取文件与状态、打开页面、切换已有状态/主题、调整视口、键盘遍历、点击不产生真实副作用的界面、截图和检查 computed style。不要提交表单、写数据、安装依赖、改文件、重启不属于本轮的服务或“顺手修复”。不确定是否有副作用就停止该动作并标明限制。

`complete` 只表示本轮审查已经执行并返回发现，不表示页面通过；通过与否由 `site-check` 根据实际证据判断。

## 2. 四个设计判断

| 判断 | 通过时能看到 | 典型失败 |
| --- | --- | --- |
| 方向有来源 | 内容主角、设计主线、色彩、字体角色和构图能回到项目事实 | 通用紫色、默认 Inter、行业模板、搜索首条直接落地 |
| 字面成立 | 角色清楚，字阶、行高、行长、中西文和数字对齐稳定 | 全页字号接近、辅助文字过小、中文标题负字距、数字抖动 |
| 材料真实 | 颜色有采样来源，素材有出处/许可/正确裁剪，缺口如实 | 灰块冒充图片、无来源图、生成内容冒充证明、随机色板 |
| 构图有重心 | 主任务获得相应视觉重量；缩到 25% 仍有结构和一处服务内容的细节签名 | 所有区块同等用力、大片无意义留白、满页卡片、只有装饰记忆点 |

类别惯例不是自动失败；无法解释它为何适合当前事实才是惯性。把产品名和 Logo 换掉仍完全成立，通常说明方向过于通用。

## 3. 排版

按角色检查 `display / heading / reading / ui / data-or-code`，不是只看字体名：

- 连续正文默认不低于 16px、行高约 1.7；标签通常不低于 14px；12px 档不承担关键阅读。项目成熟系统可有有依据的例外，但必须在实际设备可读。
- 连续中文正文行长约 28～42 个汉字；窄屏随内容缩短，不把长段铺满超宽容器。
- 中文标题 `letter-spacing` 默认 0，不机械套用西文负字距；检查标点、引号、避头尾、中西文混排和换行。
- 表格、金额、计时或纵向比较的数字使用 tabular nums 或等宽数字；小数点、单位和正负号对齐。
- 系统/开源字体优先；若用网络字体，核对许可、中文覆盖、回退、加载失败和离线能力。**加载字体必须配系统栈回退**：断网或字体加载失败时，首屏与主任务版式不得破裂或大面积重排；允许外部资源作增强，不允许它成为唯一可用字体。字体未加载成功时不得以目标字体结论验收。
- 不用全大写、字距或浅色小字弥补层级；层级主要靠尺度、字重、位置和留白。密集界面与 B 端/SaaS 严守“字重与颜色胜于字号”：不靠机械放大字号拉层级，同一个基准字号（如 14px）优先通过 `600/primary`（主值）、`500/secondary`（标签）、`400/muted`（辅助信息）三阶字重与对比度明确拉开。
- 标题换行推荐 `text-wrap: balance`，长正文推荐 `text-wrap: pretty` 避免末行孤字。
- 界面里不出现破折号（Dash Ban）：标题、标签、按钮、正文和微文案里的 `—`（em-dash）与 `–`（en-dash）都算典型 AI 痕迹；数字、日期和版本范围用普通连字符 `-`，其余关系用逗号、句号、冒号、括号或分栏表达。
- 文案措辞按 Agent 指令文件的《说人话》写（`AGENTS.md`；分发根 `agent/Agent.md`）。中西文的空话都算：中文的“极致、一站式、赋能”，英文的 Elevate、Seamless、Next-Gen，都是没有信息的词。
- 涉及中文或中西文混排时，严格遵循 [中文排版规范](chinese-typography.md)，包括系统字体栈、行高 1.5~1.75、字重 500/600 避坑、盘古之白与暗色 AAA（7:1）防线；正文与 UI 严禁斜体。
- 主行动按钮（CTA）文案控制在 6 个汉字（或 3 个西文单词）以内，桌面端不折行；全页表达同一个转化意图的按钮用同一句话。

检查 computed style 和真实换行，不只读源码声明。

## 4. 色彩、材质与素材

颜色来源优先级：现有品牌/设计系统 → 实际页面/用户素材 → 业务对象的材料属性 → 检索结果仅作候选。收敛为语义角色：`canvas / surface / text / text-muted / accent / on-accent / border / border-control / focus / success / warning / error`。

- 在渲染后的实际相邻色对上检查正文、按钮、链接、边框、焦点、选中和每个状态；token 表通过不代表页面通过。
- 状态不能只靠颜色表达。深色主题不是亮色反相，需独立看彩度、层次和焦点。
- 一个主要强调色通常足够；第二强调色要有业务语义。状态色不承担品牌装饰。单一 Filled 强调原则：同一视口内 Filled 实色主行动按钮只允许一个，同级次要操作必须保持 Neutral，杜绝多主色争抢视觉焦点。15° 色相安全阈值：相差 15° 以内的色相视为同色，严禁在同一界面混用微小色偏的同族色。
- 半透明、图片叠字、悬停/按下、动态叠层和色觉辨识需人工看；自动比值只守下限。
- 表面微步进与阴影工程：浅色模式推荐分层透明微阴影（1px 外环 + 微深度阴影，如 `0 0 0 1px rgba(0,0,0,.06), 0 1px 2px -1px rgba(0,0,0,.06)`），拒绝发黑粗重的投影；深色模式因吸光弃用扩散阴影，改用 1px 微亮半透明外环边框（如 `0 0 0 1px rgba(255,255,255,0.08)`）；输入框背景应比画板微暗以营造容纳内容的内嵌凹陷感，下拉与浮层必须高出父表面一级。图片与卡片建议加 1px 低不透明度外轮廓以获稳定深度感：浅色模式推荐纯黑 `oklch(0 0 0 / 0.1)` 或 `rgba(0,0,0,0.08)`，深色模式推荐纯白 `oklch(1 0 0 / 0.1)` 或 `rgba(255,255,255,0.08)`；严禁使用 zinc/slate 等近黑近灰色做微透明描边，避免因拾取底层色彩导致边缘发脏。

每个素材记录来源、性质、许可/授权、日期、用途、裁剪和 alt。**加载字体同样按素材登记**（来源、许可、子集范围、回退栈、加载失败时的降级表现），不因为它是 CSS 就免登记。使用顺序：用户真实素材 → 一手官方来源 → 许可清楚的公共素材 → 经用户允许的生成素材 → 有设计的缺失状态。不要创建账号、绕登录或抓取受限内容。通用氛围图若去掉后信息无损，通常不应加入。

评价、指标、客户 Logo 与其他社会证明没有来源时不得写成正式文案或渲染成界面元素；`design.py lint-ui` 把占位图冒充客户 Logo、Lorem 评价和编造星级评定确定性判为硬失败。

反 AI 塑料味硬防线（Anti-Slop Hygiene）：
- **材质与色彩去油**：背景与正文避免生硬的纯黑（`#000`）与纯白（`#fff`），改用柔和的 off-black（如 `#111`、`neutral-950`）与 off-white；严禁未经推导直接使用默认 AI 亮紫/霓虹发光（AI-purple）。
- **单边粗色条禁令（Stripe Ban / No Border-Left Callout）**：严禁在卡片、提示块（Callout/Admonition）、修订说明、引用或状态面板上使用 `border-left: 3px/4px` 或 `::before` 满高竖条作为视觉强调方式。单边粗色条严重破坏圆角对称性与现代卡片质感，多卡片纵向并列时会产生视觉栅栏噪音，是典型的 AI 生成痕迹。强调与提示必须改用：全封闭柔和微描边（1px 全包围微边框 + 3%~6% 低饱和浅底，四角对称圆角）、语义胶囊徽章（Badge/Pill）、状态微点（Status Dot）或精细线框矢量图标。
- **杜绝刻板假名与虚假精密（No Jane Doe Effect）**：严禁在演示数据与文案中出现 John Doe、Jane Doe、Acme Corp、Nexus、SmartFlow 等模板化假名与假品牌；严禁编造 `99.99%`、`1234567` 等假装工程精密的虚构数字。
- **拒绝 `<div>` 伪造假截图**：严禁用纯彩色方块和伪造进度条拼凑假终端或假仪表盘作为背景装饰；无真实产品截图时直接呈现真实组件或保持结构留白。

## 5. 构图、密度与响应式

- 首屏只有一个主重心。尺度差异应真实可感；不要靠阴影和渐变制造虚假层级。
- 缩到 25% 看主轴、分组和留白是否仍可辨；再回到 100% 看基线、边缘、间距和细节签名。
- 留白必须建立关系或节奏。密度由任务频率、数量和内容决定，不由“高级感”决定。工具/仪表盘面板采用 workbench-tight 紧凑密度（12~16px 间距与内边距），展示区适当舒展，避免全屏均分间距的单调平铺。组间距应至少为组内间距的 2 倍（如组内 8px、组间 16px+），否则分组信息将退化为视觉噪点。
- 同心圆角铁律：嵌套圆角必须满足 `outerRadius = innerRadius + padding`，严禁内外设置相同圆角半径导致内切突兀或视觉破损。
- 在真实长标题、空数据、极长列表、错误消息、多位数字和缺图下检查；极端内容要各自有设计，不靠截断掩盖核心信息。
- 断点从内容失效处得出。至少检查 375px、768px、1440px 的代表结果；移动端按任务重组，不能隐藏核心信息来假装适配。
- 动效必须表达空间、状态或因果，使用少量共享节奏；无意义动画删除。验证 `prefers-reduced-motion` 后信息和操作仍完整。高频操作（>100次/天、快捷键、命令行调出、表格行切换）零动效以防操作迟滞；下拉与 Popover 展开中心必须匹配触发源（origin-aware）；按压反馈使用 `:active { transform: scale(0.96); }`；动效仅对 GPU 合成属性（`transform`, `opacity`）过渡，严禁 `transition: all`。
- 动效工程规范：交互状态变化强制使用 CSS transition 保证可随时被用户操作反向中断（Interruptible），严禁用 keyframes 锁死简单状态过渡；首屏初始渲染跳过入场动效，防止加载闪烁；弹窗与浮层入场起点禁止从 `scale(0)` 膨胀，必须使用 `scale(0.95) + opacity: 0`；UI 动效时长上限 300ms（按压 100~160ms，菜单 150~220ms，弹窗 200~280ms）；推荐绑定工业级缓动曲线 `--ease-out: cubic-bezier(0.23, 1, 0.32, 1)`（严禁 `ease-in`）、`--ease-in-out` 与 `--ease-drawer`；双图标离散切换推荐采用绝对定位 cross-fade（scale `0.25 -> 1`，opacity `0 -> 1`，blur `4px -> 0px`）。该上限约束状态过渡与 UI 反馈；营销页的入场与滚动叙事动效不受此上限约束，但仍须满足 `prefers-reduced-motion` 与“高频操作零动效”。手写 rAF 时循环体内不得读布局（`getBoundingClientRect`、`offsetWidth`、`getComputedStyle`），每次读都会强制同步重排，是这类代码掉帧的常见来源；持续运行的循环在离屏或标签页隐藏时停掉。
- **营销站、品牌站和活动页的动效主张与节拍表见 [动效](motion.md)**：四拍以内、首屏一拍、零依赖手法、每拍写明服务哪条内容。减少动态下定格在构图最好的一帧；以“看不见”为起始、等触发器才出现的元素，在减少动态或脚本失败时是永久不可见的，最终态必须是作者态。

两个视觉候选还要做交换检查：统一色板/字体、关闭阴影后，主布局容器、核心组件形态、信息密度与首屏重心仍须不同，否则只是换肤。

**生成式默认骨架的识别（人工判断，不做 grep）**：Hero + 三张同规格卡片 + 单一 CTA、满页等权卡片、每区块各套一层 surface、无来源的渐变/玻璃/光晕、装饰性 keyframes——这些是生成式答案的统计惯性，值得怀疑。但它们是审美判断，不是可判定的文本事实：本包自己的落地页与数据看板指南就推荐其中若干形态。因此**不设自动检查**，由审查者在具体语境里判断：

- 逐个问"这个形态由哪条项目事实支持"；答不出就是默认骨架，改为由内容推导的结构；
- 形态出现在营销落地页且与 `landing-page.md` 选定的版式一致时，是合理采用，不是默认；
- 同页多种默认形态叠加（Hero+卡片流+pill 云+渐变+装饰动画）时，即使每项单独可解释，整体仍是生成式产物，按 §8 列为发现。

`design.py lint-ui` 不报告此类问题；它只报告能从源码文本确定判定的事实（图标体系混用、Emoji 冒充图标、伪造证据、排除能力复现、候选换肤）。

## 6. 任务、状态与可访问操作

根据表面选相关项，不为不存在的能力制造状态：

- 主任务从入口到结果可完成；成功、失败恢复、中途退出和再次打开的保留/改变规则一致。
- 弹窗（Modal）、抽屉（Drawer）与浮层滚动容器强制添加 `overscroll-behavior: contain` 隔绝滚动穿透；桌面端左右并列滚动分栏容器必须显式声明 `min-height: 0` 保证可用高度不溢出。
- 高频操作保持稳定的列表/详情关系、当前位置和处理反馈；长阅读保持可扫读层级、可预测返回和合理行长。
- Loading、empty、error、disabled、saving、success 等状态只在业务可达时出现；状态文案说明发生什么和下一步，不用 Toast 替代唯一恢复路径。
- 键盘顺序与视觉顺序一致；焦点可见且不被 sticky/弹层遮挡；弹层关闭后焦点返回合理位置。
- 图标按钮有可访问名称；表单有可见 label、关联错误和提交失败后的聚焦/摘要机制。表单提交失败后，视口平滑滚动并自动聚焦（focus）到首个错误控件；输入框严禁拦截 paste 事件（保障密码和验证码正常粘贴）；表单未填写完毕时严禁直接禁用提交按钮（避免用户无法感知缺漏项）；点击提交后保持原文字并附加 Spinner 禁用重击。
- 破坏性/高危操作分级防线：普通危险操作提供确认弹窗或 3~5 秒可撤销 Toast（Undo）；工作区/账号/全库删除等重度不可逆操作采用“输入指定名称解锁确认按钮”模式，确认按钮默认 disabled。
- 触控目标默认至少约 44×44px（这是本包的项目默认操作高度；WCAG 2.2 AA 的合规下限是 24×24 CSS px，两者不是同一约束，不得互相替代）；关键操作不依赖 hover；移动端全局添加 `touch-action: manipulation` 消除 300ms 双击延迟；窄屏安全区使用 `env(safe-area-inset-bottom)` 适配，软键盘和输入法组合态不遮住当前字段或主操作。
- 动词先导原则（Verb-First）：按钮标签必须以动词开头（如“保存草稿”、“删除项目”），杜绝无业务语义的“确定”、“提交”或“OK”；二次确认弹窗的确认按钮必须直接写明后果动作（如“确认删除”而不是“是”），让用户不读弹窗正文亦能明确操作后果。删除、发布、付费、权限、隐私等高后果操作要说明影响、确认边界、结果凭据和实际可用的恢复方式；不要用虚构撤销安慰用户。
- 常规 UI 默认使用 Lucide 一套图标体系；用户或现有工程已明确指定其他体系时**以该指定为准**，并如实写入合同 `icon_system`。无论采用哪套，同一界面只允许一套体系；不以 Emoji 或 Unicode 字符充当按钮、导航或状态图标，例外要有产品依据并核对识别、一致性和可访问名称，记录进 [页面设计合同](surface-brief.md) 的 `icon_system` 与 `icon_exceptions`。`design.py lint-ui` 对此确定性硬失败：同界面混用多套图标体系，或 Emoji/Unicode 充当图标而无明确例外；实际体系与声明（未声明时按默认 Lucide）不一致则告警，由 Agent 决定对齐代码还是把选择写进合同。检索返回的图标条目只提供语义与命名，其中的库与 import 代码不采用。
- 组件血统门禁（Use What Exists）：按钮与链接必须使用原生 `<button>`/`<a>`，严禁 `<div onClick>` 伪造交互；复杂状态控件（Select, Popover, Dialog, Dropdown, Tabs）优先组合成熟无头无障碍基模（如 Radix, React Aria, Headless UI 等），严禁无 ARIA/无键盘支持的手搓实现；样式强制消费语义 Token，严禁散落裸十六进制或堆砌重复 utility。

## 7. 图表与数据界面

只有存在图表时才检查：

1. 先确认数据关系是比较、趋势、分布、组成、相关、层级还是流向；图型必须服务该关系。
2. 标题、单位、时间范围、基准和异常值清楚；Tooltip 不是唯一信息来源。
3. 指标卡（Metric Card）明确视觉焦点：英雄数字通过字号与字重（`tabular-nums`）处于统治地位，标签与说明降级，严禁并列指标卡均分权重。
4. 系列不只靠颜色区分；提供图例、直接标注或形状，并有同等意义的文本/表格替代。
5. 键盘与屏幕阅读器能获得关键值；窄屏减少装饰和同时展示的系列，而不是把图表横向挤扁。
6. 需要候选时只查询 `design.py research "<关系 情境>" --domain chart`，再以真实数据形状筛选。
7. 技术标识与路径呈现：文件路径、Git SHA 与哈希标识使用 `font-mono`，中间目录段（如 `./`、`node_modules`）可微淡化层级；排版中视觉截断（`truncate`）时，**必须在 `title` 属性中保留完整未截断路径**；密集列表时间优先紧凑格式（如 `45s`、`8m`、`3h`、`12d`），并在 hover/tooltip 提供绝对时间；高频或动态变更的数值一律强制使用 `tabular-nums` 防止横向抖动。
8. **图形必须由数值驱动**：柱高按 `height = 值 / 最大值` 从零基线算出，不用 `(值 - 最小值) / (最大值 - 最小值)`——柱的面积编码数值，基线必须是零。柱状只用于类别比较，时间趋势用折线或面积；柱子不超过约 12 根，宽度不小于柱间距，每根有轴标签（密集时每隔 N 根标一个，不竖排）。所有柱子等高、顶到容器上沿、细过间隙或缺轴标签（条形码图）、用写死的宽度或高度冒充图表，任一出现即不成立。动画只作用于填充：柱子高度先按数值定死，再做 `scaleY` 生长，容器高度不参与动画；`prefers-reduced-motion` 下定格。

## 8. 三路结果与修正循环

始终分开报告：

```text
design：方向来源、字面、材料、构图
task_state：主路径、反馈、恢复、再次打开、键盘/触控
mechanical：溢出、断链、缺资源、console/build、色对等自动检查
（`design.py lint-ui` 覆盖其中可由源码文本判定的部分，并在报告的 `not_covered` 里列出它看不到的项）
```

任一路通过都不能代替另外两路。制作分支把发现按“会阻止当前设计判断 → 影响主要任务 → 工艺问题”排序，完成一次集中修正后，用相同评审帧复验；条件变化就新建证据。只读分支按同样优先级直接返回发现，不实施修复。

最终记录最小集合：结论、页面/状态/视口、可复现观察、影响、建议方向、证据位置和未执行原因。每个发现保留 ID、来源、预期、实际、位置和复验状态；制作分支只报告真实自检复验，只读分支交回 `site-check` 闭环。没有发现不等于已执行通过；大量截图不能替代判断。
