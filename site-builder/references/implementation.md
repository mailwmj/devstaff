# 按可体验切片实施

## 1. 综合，不重新访谈

页面结构、视觉风格都确认，并取得开发授权后，以 `.site/brief.md` 定义范围，以 `.site/design/surface-brief.md` 定义页面设计，以源码和现有约定定义工程现实。体验稿用于理解选定效果，不凌驾于页面设计合同。上游风格检索、工艺规则和来源记录只由 `site-design` 解释；builder 消费已经项目化的合同 ID，不直接调用检索器或从预设重新挑选。已确认内容不重问；只有新发现的冲突、高风险事项或必须显著缩减范围才暂停。

新建、整体改版、主流程或信息结构变化进入计划前，页面设计合同须覆盖适用的页面地图、区块清单、Design Token、响应式合同、组件状态、文案台账、素材地图和 `VA-*` 视觉验收标准。缺少普通实现细节时交回 `site-design` 按选定方向补齐，不打断创作者；缺少会改变结构、视觉或高风险边界的决定时回到对应门禁。简单修改无需计划。中小型首版的 `.site/implementation-plan.md` 只记录业务规则、数据生命周期、角色权限、外部服务、技术选择、少量纵向切片及来源 ID 映射，不复制合同全文。

先核对合同的“首版承诺 × 原型覆盖”：每条 `simulated / missing` 都必须进入正式切片和适用检查，`covered` 也不是正式能力通过。原型没有控件、只做“卖1”或尚无持久化，不缩减 brief 的承诺；缺少补齐责任时交回 design 修正交接，不要求用户重新确认已确认的能力。

## 2. 使用纵向切片

实施顺序由少量纵向切片组成。每条都贯穿完成该能力所需的数据、规则、界面和检查，完成后可以独立体验；不要按“先全部数据层、再全部接口、最后全部页面”横向铺开。

每条使用：

```markdown
## 切片：<用户获得的完整能力>

**前提：** <开始时已存在什么>
**操作：** <用户做什么>
**可观察结果：** <界面、数据或外部结果如何证明成功>
**失败恢复：** <失败时保留什么、用户如何理解并重试或改走安全路径>
**中途退出：** <取消、返回或关闭后会保留/撤销什么，如何继续>
**适用状态：** <本能力实际需要覆盖的空、加载、错误、边界或权限状态>
**交互约束：** <本切片兑现的 required / recommended / confirm / excluded 条目或 ID>
**视觉落实：** <选定方向如何落到本切片的页面、控件、素材和状态>
**依赖：** <真正阻塞它的前一切片，或无>
**适用检查：** <自动测试、浏览器任务、视觉状态、再次打开>
```

一个简单项目可以只有一个切片。切片数量服从首版，不为制造计划而过度拆分。先做通核心任务，再扩展已确认页面和状态。失败恢复、中途退出和适用状态按真实风险选择，不为每个页面机械制造全套状态：

- 集合、筛选或搜索考虑首次空白、无结果和清空条件；
- 异步操作考虑加载、超时和重试；
- 表单或写入考虑校验、提交中、防重复以及失败后保留输入；
- 可变内容考虑零值、缺失值、长文字和缺图；
- 持久化、导入或破坏性操作考虑失败、取消、后果与恢复，并在适用时再次打开；
- 权限、多人共享和离线只在已确认首版确实包含时覆盖，不自行扩张范围。

交互合同中的 `required` 必须进入相应切片；`recommended` 采用或记录由项目事实支持的偏离理由；`confirm` 先取得业务决定再实施，不能让体验稿中的模拟替代确认；`excluded` 不得进入导航、控件、文案、数据结构或占位状态。中国本地化只落实已知的语言、格式、输入和渠道条件，不自动接入微信、短信、支付、实名或数据收集。

计划中沿用来源引用维护范围覆盖表，确保每条已确认能力、排除项及适用规格都有去处。原型状态引用合同，不复制原型表；随切片补实际实现位置，交接前完成全部适用行：

| 来源引用 | 能力、规格或排除项 | 原型补齐事项 | 对应切片 | 正式实现位置 | 对应检查 | 处理 |
| --- | --- | --- | --- | --- | --- | --- |
| `BR-03` | 一次卖出可减多个 | 原型只演示卖1；补数量操作与正式扣减规则 | 多件卖出 | 数量控件、扣减入口与数据规则的实际路径 | 卖3：库存10变7；适用数量边界 | 实现 |
| `EX-01` | 在线支付 | 不适用 | 无 | 无 | 范围排除检查 | 明确不实现，界面不得暗示可支付 |
| `IC-03` | 失败后保留输入 | 按合同实际缺口 | 相应写入切片 | 输入状态与错误恢复的实际路径 | 提交失败与重试 | 实现 |
| `VA-06` | 375px 主行动可达 | 按合同实际缺口 | 核心任务切片 | 核心页面与主行动的实际路径 | 手机视觉与核心任务 | 按 ID 验收 |

交给 Checker 时按 [上下文契约](../../site-brief/references/context-contract.md) 返回 `coverage`，目标引用实际切片、实现位置和待执行检查；未映射来源保留 `gap`，不能用一个“核心流程”目标掩盖未兑现条件。简单修改直接在回执中给受影响来源与检查，不为表格创建计划或 `.site`。

## 3. 把视觉方向落实到完整任务

把用户选定的页面结构、交互合同和正式实现规格应用到实际任务表面，而不只打磨首页或首屏。按 `PG-* / SC-* / CP-* / RP-* / TX-* / AS-* / VA-*` 保持实现可追溯；新建和整体重做至少核对核心页面与最复杂的操作表面（如表单、弹窗、详情或结果页），简单局部修改只覆盖受影响表面。

- 排版角色、空间节奏、控件层级、素材裁剪和状态反馈在同角色组件与不同页面间保持一致；
- 默认、悬停、按下、焦点、禁用、加载、成功与错误状态按适用范围完整实现，不能只有默认态精致；
- 动效服从一组克制的快/常规/慢节奏，只解释状态变化、层级切换或操作反馈，不强制环境动画；
- 尊重系统的 `prefers-reduced-motion`，减弱或取消非必要运动，同时保留结果反馈；
- 沿用已有成熟设计系统；没有现成系统时再把已确认意图收敛为少量共享变量和组件规则。token 一致只是手段，不能代替实际渲染质量。

## 4. 行为反馈循环

业务规则、状态转换、计算、导入导出、持久化、权限、外部服务边界和 Bug 修复优先建立能在错误行为出现时失败的检查。测试通过公开行为观察结果，不绑定私有函数、调用次数或内部文件布局；预期值来自需求和独立例子，不照抄实现算法。

按一条切片循环：

```text
明确前提、操作、结果
→ 让检查能发现能力尚未实现或 Bug 仍存在
→ 写最少实现使其通过
→ 运行项目原生构建和相关检查
→ 整理而不扩张范围
→ 进入下一条
```

纯展示页、文案和局部样式不强制自动测试，使用构建和真实渲染检查。

## 5. 实现约束

- 一份共享导航和布局来源，页面职责清晰；
- 数据使用稳定 ID 和单一事实来源，统计由记录推导；
- 按需要分开业务数据、UI 状态和数据访问，不对展示站强加复杂分层；
- 示例与正式数据隔离；写入失败保留输入；导入先校验和预览；结构变化先备份并验证迁移；
- 浏览器存储绑定设备、浏览器和网址，不承诺永不丢失；跨设备或多人目标使用匹配的持久化方案；
- 修改已有工程先看调用者和约定，业务、数据或访问方式变化时扩大回归范围；
- 不实现首版范围外的“顺手功能”。

完成每条切片不等于交付；最终由 `site-check` 按真实入口独立验证。

交接前附契约的 `findings`，沿用上游问题 ID，列出修复和实际自检复验；尚未复验为 `fixed_unverified`。冻结后不更新计划或源码；Checker 以自己的新冻结版本证据核对这些问题，不沿用 Writer 自评关闭独立验收。
