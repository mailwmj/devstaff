# 运行、依赖与正式实施

## 1. 先检查环境

检测宿主、操作系统、现有运行时和项目原生启动方式，不假定 Python、Node.js、npm、Docker 或浏览器已安装。已有工程沿用其工具链，不运行初始化覆盖。

权限分两类：

- **可自主处理**：项目目录内的 npm/pip 等依赖、项目虚拟环境、开发服务器、非破坏性的端口调整、构建和测试。
- **先说明并确认**：安装系统级 Node.js/Docker/数据库/浏览器，管理员权限，修改系统环境变量，影响其他项目的全局包或服务，付费/云资源，第三方登录、密钥、域名和真实敏感数据。

说明时使用结果语言，例如安装内容、磁盘/系统影响、是否常驻和用户需完成的动作，不把命令本身当解释。Agent 能解决的普通报错不推给非技术用户。

## 2. 选择运行方式

技术栈服从已确认范围，不强制零依赖或双击 HTML。展示页可保持静态；复杂交互可选择合适框架；需要可靠长期或共享数据时使用合适服务与数据库，而不是强行塞进浏览器存储。

新建项目也可在方案和开发授权明确后使用随包 starter：

```text
python3 /absolute/site-builder/scripts/site.py init /absolute/project --template static --title 名称
python3 /absolute/site-builder/scripts/site.py init /absolute/project --template tool --title 名称
python3 /absolute/project/.site/preview.py
```

Python 工具要求 3.10+；Windows 可能使用 `py -3`，Mac/Linux 通常使用 `python3`，以实际检测为准。starter 只接受空目录或仅含 `.site` 记录的目录；后者保留原 brief/state，并在输出中标明是否需要由 `site-brief` 记录推荐 runtime。空目录会创建 `discovering` 默认状态，调用者必须立即把本轮已经获得的方案、视觉和开发授权交给 `site-brief` 恢复后，才能进入 `building`。starter 只是启动基础，不是视觉体验稿或用户项目完成品。

`site-builder` 的随包预览只服务项目 `web/`，默认回环地址和端口 8765，不是生产服务器。端口占用时不杀无关进程；无持久数据的首次预览可换端口。浏览器存储已绑定旧网址时，先确认旧入口或导出迁移，不能静默换来源导致用户以为数据丢失。

## 3. 启动与检查交接

启动后检查实际就绪、入口可达且对应正确项目。脚本文件存在不等于已验证跨平台双击；最终提供当前环境实测的再次启动方式。离开会话后仍需启动进程时，要清楚说明。

更新使用说明为真实业务和实际命令，并说明数据位置、备份恢复与已知限制。实现完成后把真实入口、启动命令、数据位置和本轮范围交给 `site-check`；不要用开发服务器当次可用代替其再次打开检查。不默认生成 `acceptance-guide.md`。

默认不公开端口、上传数据或创建云服务。用户要求部署或分享时读 publish.md；新增费用、账号授权、公开内容和数据迁移须确认。

无执行能力时仍可交付文件和准确命令，但必须明确哪些运行、交互和视觉没有实际验证。
