# 组件和技术选用

已有工程优先沿用其框架、组件库、主题和调用方式，不为本套 Skill 迁移技术栈或混装重复控件体系。新项目根据首版范围选择最小合适方案；普通技术选择由 Agent 负责。

| 项目情况 | 优先选择 | 边界 |
| --- | --- | --- |
| 成熟设计系统 | 沿用现有组件和主题 | 视觉变化交给 `site-design` 确认 |
| 小型静态/原生 JS | 语义 HTML 和原生控件 | 复杂行为仍需实现和验证 |
| 新 React 工具 | 评估当前兼容的成熟组件方案 | 按需安装，不把组件库当整页设计 |
| 复杂弹层、菜单、组合选择 | 沿用已装基础，必要时选择一种成熟可访问方案 | 不叠加两套焦点和弹层体系 |
| 图标 | 既有图标集；没有时选与技术栈和视觉语法一致的成熟集合 | 图标按钮提供可访问名称 |

常规操作和状态标识（如搜索、添加、删除、警告）不得用 Emoji 代替图标；用户内容本身是 Emoji 不受此限。已选产品/视觉方向明确让该操作或状态图标使用 Emoji 时可例外，并在设计交接中说明依据。离线要求限制最终运行时的网络依赖，不禁止开发时使用项目本地依赖：按需把成熟图标集构建进交付产物，或把所用 SVG 及必要字体放入交付目录；单文件交付须把所用图标嵌入文件。不得让离线页面从 CDN 或 Skill 安装路径获取图标。

按任务选择结构：

- 少量平级视图使用简单导航；只有跨模块持续切换才需要侧栏；
- 阅读用连续正文，比较记录用列表/表格，作品内容用图集；卡片只表达独立实体；
- 短动作可用对话框，频繁或长时间编辑提供稳定工作区；
- 少量固定选项优先原生 select/radio，大量可搜索选项才使用 combobox；
- 校验和保存错误靠近字段并保留输入，toast 不替代核心结果；
- 宽表在窄屏保留关键能力或局部滚动，不隐藏功能假装适配。

具体视觉 token、中文排版、控件状态和外观基础由 `site-design` Skill 负责。实现时把选定规则映射到项目现有主题；最终运行不能依赖 Skill 安装路径。
