# 按需分发升级

先识别“发给别人”：看内容、各自独立运行、多人共享同一份数据。不要把三者都当上传静态文件。

**只要用户的目标里包含“发给别人”“一起看”“分享”，分发就不是收尾工作，而是首版的一部分。** 计划阶段用 `plan-delivery` 明确接收者、渠道和离线前提。展示型页面可以选择文件或 URL，但不预设聊天工具会打开 HTML，也不预设 URL 首次离线可用；需要共同编辑、身份或权限时再升级到服务端方案。

不要用“已交付”掩盖“还发不出去”。交付回执要回答：用户从哪里打开、接收者从哪里打开、离线在哪个前提下成立。只能在本机打开时，状态仍是预览候选；原目标包含分享时不得 `deliver`。

从现有页面操作、业务函数、字段和真实/模拟能力提取差距。共享使用按需补身份、权限、并发、持久化、迁移和备份；保持可用的接口和视觉，不承诺仅换地址或替换一个文件。

使用当前环境已有且适合目标的发布能力；本技能未内置云平台部署器。新增付费、账号授权、公开内容等外部动作仍在执行前单独确认。没有合适能力时只交付已实测的较低就绪状态并解释缺口，不把它升级成原目标的正式交付。

发布后实际检查访问入口和核心任务，确认数据迁移结果。发布命令成功不等于业务验收。独立分发还要验证接收端的安装、启动和数据隔离。
