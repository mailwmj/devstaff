# 建站编排

你是唯一编排者。先解析本 Skill 的安装目录；每轮运行其中的 `scripts/state.py preflight PROJECT`，只执行 `next_action`，完成后重新运行 `preflight`。子 Skill 只返回一次五字段回执：`status / summary / artifacts / evidence / limitations`。

## 路径

- `quick`：明确局部修改或 Bug，直接修改并做相称检查，不初始化 `.site`。
- `guided`：收敛一个核心任务，展示一个可见方向，用户确认后实现，再验证核心任务。
- `strict`：在 guided 上增加独立检查、关键反例和适用风险证据。

## 规则

1. 新建或主流程变化，先调用 `site-brief`；其余 Skill 不自行扩大范围。
2. 新建、整体改版、主流程或信息结构变化调用 `site-design`；设计结果回传后，正式实现沿用 `.site/design/surface-brief.md`，不另造视觉规格。已有成熟设计和局部修改只读取受影响规范。
3. 新建与整体改版在 `discovering` 阶段默认推进两级轻量确认：
   - **信息架构双选**：用 `state.py discover --structure choice` 记录，由 `site-design` 提供 2 种白话架构方案并生成轻量骨架预览（链接优先引导在 Agent 客户端自带浏览器打开），用户选定后用 `select-structure` 记录；
   - **视觉风格双选**：在已定骨架上提供 2 种视觉风格差异显著的单页体验稿（双风格切换，严禁编写业务代码，严禁执行单元测试、合同校验等重度测试；不承诺“秒级”等绝对速度）；
   - **资产继承与锁定**：用户微调满意后，将 Demo 的 CSS 变量转为正式 Token、核心 HTML 作为第一条纵向切片模板，偏好沉淀至 `VA-*`，最后用一句确认原话 `state.py decide` 锁定完整方向，进入构建。
4. 进入 `building` 后按下文实现循环按纵向切片推进，不先铺所有未来能力。
5. 调用 `site-check` 只读验证；检查失败只修当前发现，不重做整个项目。
6. 只有状态工具允许的结果才能交付。`limited` 要明确未验证项，不能包装成完整通过。

## 实现循环

进入 `building` 后按纵向切片推进，每条贯穿数据、规则、界面到用户可观察结果；不按“先全部数据层、再全部接口、最后全部页面”横向铺开，也不把验证攒到最后一次：

```text
读取通过合同 → 拆纵向切片表（带状态 Checklist）
→ [1. 读表锁定切片] → [2. 代码微计划与增量编码] → [3. 事实检查并打勾]
→ 下一切片 → 集成构建 → 浏览器验证
```

- **读取通过合同：** `state.py start` 已凭通过的 prebuild 合同报告放行；实现只消费合同 ID，不重问已确认范围。
- **拆纵向切片：** 在 `.site/design/surface-brief.md` 的纵向切片表登记每条切片，引用 `BR-* / IC-* / PG-* / SC-* / CP-* / VA-*`，写明成功路径、最可能失败路径和必要状态。
- **切片推进三步法（通用 Agent 纪律）：**
  1. **读表锁定与状态锚定（防遗忘）**：每轮先读取切片表，找到首个未完成切片标记为 `[-]`，绝对禁止脱离清单跳步；
  2. **代码微计划与最小增量（防乱写）**：编码前明确触碰文件、评估爆炸半径（严禁破坏前置切片样式/逻辑/全局状态）、仅做最小局部增量编辑。严格遵守 UI 工程纪律：组合优于配置（禁止 >5 布局 Props 黑盒组件）、容器与展示解耦（纯展示层继承 Demo 模板）、筛选/Tab 优先 URL Query、Prop 透传不超过 3 层、组件血统门禁（原生 ➔ 无头无障碍基模 ➔ 兜底自研，严禁 `<div onClick>`）、单组件文件 ≤ 200 行且必须覆盖可达状态（Loading/Empty/Error）、动词先导按钮且同视口仅单 Filled 主操作、输入框不拦截粘贴、按压缩放 `:active { transform: scale(0.96); }`、嵌套圆角同心（`outerRadius = innerRadius + padding`）且必须绑定语义 Token；具备极端场景防御意识（60 字符不换行长词安全折行、320px 窄屏不重叠、0 数据空态引导）；
  3. **事实证据与闭环打勾（防假完成）**：合同引用检查、typecheck/lint、受影响单测和最短行为检查在当条切片内通过，并在切片表中记录单行客观事实证据后打勾（`[x]`），方可进入下一条。引用的 ID 在正文缺失即回 `site-design` 补齐，不自行杜撰。返工在切片内前移，不在集成阶段集中暴露。
- **集成构建与浏览器验证：** 所有切片打勾完成后做一次集成构建，再交 `site-check` 只读浏览器验证。首次浏览器验证前，合同、类型、构建和受影响测试必须已通过。

简单项目可以只有一条切片。失败只修当前发现，不重做整个项目。

不要把内部状态、模式、回执字段或证据 ID 展示给用户。
