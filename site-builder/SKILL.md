# 渐进式建站

用户只需描述目标和反馈。此 Skill 负责自然语言路由、两个确认门禁、全部正式源码修改、实施、修复和交付；首版梳理、可见实验与独立检查由其他 Skill 负责。

## 执行

1. **识别请求和工程。** 定位用户指定项目，读取源码、原生说明及已有 `.site` 记录。区分完整建设、参考建设、已有设计、局部修改、Bug、检查并修复、只梳理、只设计、只检查与发布。明确只梳理/只设计/只检查时分别调用 `site-brief`、`site-design`、`site-check` Skill，返回其回执后停止本流程。
2. **取得首版方案。** 新建、整体改版、主流程变化或高影响需求不清时调用 `site-brief`。只有核心用户、场景、任务、可观察结果、范围和高风险未知已交代，且方案明确确认或获得适用委托，才继续；否则停在方案门禁。局部修改和可直接复现的 Bug 可跳过。
3. **取得可见方向。** 新建、整体改版、主流程/信息结构变化或用户要求“先看看”时调用 `site-design`。需要视觉确认的分支必须等体验稿实际展示、模拟范围说明和用户明确确认后继续；已有状态时还须由 `site-brief` 记录 `visual_confirmed=true`，尚无项目目录时保留带依据的回执并在步骤 5 初始化后记录。成熟设计和沿用现状的小修改可跳过。
4. **通过开发门禁。** 回放选定方向、核心任务、首版范围和模拟部分。获得“按这个做”“开始开发”等明确授权，或已有适用的全权委托后，才由 `site-builder` 判定开发授权。已有状态时调用 `site-brief` 记录 `development_authorized=true` 与 `stage=ready_to_build`；尚无状态时保留用户依据并在步骤 5 初始化后记录。高风险或显著范围变化仍须暂停。
5. **准备工程并计划。** 读 [运行](references/runtime.md) 和 [实施](references/implementation.md)。新项目此时选择技术栈；使用 starter 时只允许目标为空或仅含 `.site`，并保留已有 brief/state。初始化创建默认状态或返回运行配置后，立即调用 `site-brief` 记录本轮已确认方案、视觉、开发授权和 runtime，再创建必要的 `.site/implementation-plan.md`。把首版拆成少量可独立体验的纵向切片；体验稿明确演进或重写。简单修改无需创建计划或状态文件。
6. **连续实现。** 若项目已有或本轮需要 `.site/state.json`，调用 `site-brief` 校验三个门禁字段后记录 `stage=building`；再按需读 [组件](references/components.md)。从核心任务的最短完整路径开始，一次完成一个切片；业务规则、状态转换、持久化和 Bug 按风险建立行为检查。项目内依赖、构建错误和普通样式问题自主解决。
7. **独立验证和修复。** 有协作状态时调用 `site-brief` 记录 `stage=verifying`，再调用 `site-check`，传入本轮范围、`.site/brief.md`、实施计划和真实入口。根据 failed 项修复并再次检查；连续两轮没有新证据或进展时停止重试，记录 `blocked` 及恢复条件。宿主不能分派 Skill 时执行隔离的检查阶段并说明限制。
8. **通俗交付。** 以 `site-check` 的检查矩阵为准：所有本轮适用且阻断交付的项目必须 `passed`；任一阻断项为 `failed` 或 `not_run` 时保持 `verifying` / `blocked`。满足条件后由 builder 判定交付，并调用 `site-brief` 记录 `stage=delivered`。说明入口、再次启动、完成范围、体验顺序、实际检查、未检查项、数据位置与限制。发布再读 [分发](references/publish.md)。

## 快速分支

- 局部文案、颜色、间距：直接修改正式源码，再执行相称检查；不为此创建 `.site`。
- Bug：先复现用户症状，再修复并覆盖原症状，不机械重走发现和视觉流程。
- 已有设计：读取并沿用；只有整体方向或结构存在未决项才调用 `site-design`。
- 大型愿景：调用 `site-brief` 保留完整愿景并切出本轮目的地，不一次承诺完整平台。

## 协作回执

最终返回：项目入口、完成的首版能力、各 Skill 交接结果、检查矩阵摘要、数据位置、限制和下一步。`site-builder` 是开发授权和交付判断的唯一负责人，`site-brief` 是协作状态的唯一写入者；不得根据草案文件、视觉称赞或构建成功推断确认或交付。
