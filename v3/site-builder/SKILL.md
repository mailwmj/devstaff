# v3 建站编排

你是唯一编排者。先解析本 Skill 的安装目录；每轮运行其中的 `scripts/state.py preflight PROJECT`，只执行 `next_action`，完成后重新运行 `preflight`。子 Skill 只返回一次五字段回执：`status / summary / artifacts / evidence / limitations`。

## 路径

- `quick`：明确局部修改或 Bug，直接修改并做相称检查，不初始化 `.v3`。
- `guided`：收敛一个核心任务，展示一个可见方向，用户确认后实现，再验证核心任务。
- `strict`：在 guided 上增加独立检查、关键反例和适用风险证据。

## 规则

1. 新建或主流程变化，先调用 `site-brief-v3`；其余 Skill 不自行扩大范围。
2. 新建、整体改版、主流程或信息结构变化调用 `site-design-v3`；设计结果回传后，正式实现沿用 `.v3/design/surface-brief.md`，不另造视觉规格。已有成熟设计和局部修改只读取受影响规范。
3. 收敛方向时用 `state.py discover` 记录结构判断：默认 `single`；只有真正不同的信息拓扑才 `choice`，先 `select-structure` 再 `decide`，两句原话不能相同。配色、字体、圆角、阴影等纯视觉差异一律 `single`，不触发结构选择。
4. 进入 `building` 后按下文实现循环按纵向切片推进，不先铺所有未来能力。
5. 调用 `site-check-v3` 只读验证；检查失败只修当前发现，不重做整个项目。
6. 只有状态工具允许的结果才能交付。`limited` 要明确未验证项，不能包装成完整通过。

## 实现循环

进入 `building` 后按纵向切片推进，每条贯穿数据、规则、界面到用户可观察结果；不按“先全部数据层、再全部接口、最后全部页面”横向铺开，也不把验证攒到最后一次：

```text
读取通过合同 → 拆纵向切片 → 实现一个用户可观察结果
→ 合同引用检查 → typecheck/lint → 受影响单测 → 最短行为检查
→ 下一切片 → 集成构建 → 浏览器验证
```

- **读取通过合同：** `state.py start` 已凭通过的 prebuild 合同报告放行；实现只消费合同 ID，不重问已确认范围。
- **拆纵向切片：** 在 `.v3/design/surface-brief.md` 的纵向切片表登记每条切片，引用 `BR-* / IC-* / PG-* / SC-* / CP-* / VA-*`，写明成功路径、最可能失败路径和必要状态。
- **切片内闭环：** 合同引用检查、typecheck/lint、受影响单测和最短行为检查在当条切片内通过再进下一条；引用的 ID 在正文缺失即回 `site-design-v3` 补齐，不自行杜撰。返工在切片内前移，不在集成阶段集中暴露。
- **集成构建与浏览器验证：** 所有切片完成后做一次集成构建，再交 `site-check-v3` 只读浏览器验证。首次浏览器验证前，合同、类型、构建和受影响测试必须已通过。

简单项目可以只有一条切片。失败只修当前发现，不重做整个项目。

不要把内部状态、模式、回执字段或证据 ID 展示给用户。
