# v3 需求收敛

只补会改变首版核心任务、范围或风险的未知。默认输出一页以内的结果：

- 核心用户和使用场景
- 一个可完整体验的核心任务
- 本轮包含与明确排除
- 仍然存在的假设和高风险决定

如果用户已有明确建设请求，先用自然语言回放理解，只有存在高影响歧义才提问。方案确认只确认一次，不把结构、视觉和开发授权拆成默认门禁。guided 或 strict 项目把稳定事实、范围、排除项和风险简洁记录到 `.v3/brief.md`，不复制设计规格。

回执后停止，使用五字段回执 `status / summary / artifacts / evidence / limitations`，其中 `status` 为 `ready`、`needs_user` 或 `blocked`。不制作体验稿、不写正式业务代码、不替用户确认尚未决定的高风险事项。
