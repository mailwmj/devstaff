# 渐进式建站 v3：执行指令

这份文件写给 Agent。用户不需要看到其中的路径、状态或协议名。

## 唯一控制回路

```text
preflight → 执行 next_action → 产出结果 → 写入结果 → 再次 preflight
```

不要根据记忆猜下一步。`state.py preflight` 返回的 `next_action` 是当前唯一推荐动作；只执行 `allowed_actions`，不执行 `blocked_actions`。

`site-builder-v3` 是唯一编排者。`site-brief-v3`、`site-design-v3`、`site-check-v3` 完成任务后返回一次紧凑回执：`status / summary / artifacts / evidence / limitations`。它们不继续编排、不修改其他职责的产物、不宣布交付。

## 入口判断

| 请求 | 路径 |
| --- | --- |
| 明确 Bug、文案、颜色、间距局部修改 | `quick`，直接处理，不初始化 `.v3` |
| 新建、整体改版或主流程变化 | `guided`，先收敛核心任务和方向 |
| 支付、权限、隐私、共享数据、公开部署或多人协作 | `strict`，要求独立验证和适用风险证据 |
| 只梳理需求 | 交给 `site-brief-v3` 后停止 |
| 只要视觉方向或流程体验稿 | 交给 `site-design-v3` 后停止 |
| 只要检查且没有修复请求 | 交给 `site-check-v3` 后停止 |

有 `.v3/state.json` 时先 `preflight`。已有项目的局部修改不因为没有状态而被迫初始化流程。

## 用户体验

- 每轮只让用户做一个高影响决定。
- 默认给一个有依据的推荐方向；只有真实分歧会改变核心任务时才比较多个。
- 一次方向确认包含核心用户、任务、范围和可见方向，不默认拆成结构、视觉、开发三道门。
- 精简的是用户门禁，不是设计能力。新建和重大改版必须调用 `site-design-v3`；由它按任务加载设计规范、模板、Token、素材规则和工艺审查。
- 用户明确要求建设且没有新的高风险歧义时，不重复索要“开发授权”。
- 信息不足时先问最少的关键问题，不自动升级 strict。
- 不向用户展示状态名、模式或证据字段。

## 三条红线

1. 核心任务和方向未确认前，不写正式源码。
2. 高影响选择未确认前，不替用户决定。
3. 没有实际验证就不能说“已验证”；必须区分 `verified`、`limited`、`blocked`。

费用、系统变更、密钥、真实敏感数据和公开发布始终单独停下，等待用户明确决定。

## 交付

只说明入口、完成的核心任务、实际检查内容、未检查内容、数据位置和限制。不把“构建成功”说成“产品已验证”。
